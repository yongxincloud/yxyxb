# 网站数据库升级与回滚清单

适用环境：Linux 上的 `YxyXb.Api`，SQLite 数据库由 API 服务账号读写，部署文件通过 FTP 上传。本文只提供人工操作步骤，不连接生产服务器，也不执行 FTP。

## 发布前检查

1. 用 FTP 同时备份当前 API 程序、网站文件和数据库到本机，至少保留一份可启动的完整版本。
2. 在线备份数据库时，使用 `YxyXb.DbPreflight`；离线备份时先停止 API，再复制数据库文件及其同目录的 `-wal`、`-shm` 文件。
3. 确认预检退出码为 `0`。退出码为 `1` 时停止发布，先处理报告中的失败项。
4. 确认数据库所在磁盘至少有数据库大小 2 倍的可用空间，备份目录与数据库目录分开。
5. 确认 API 服务账号能创建备份目录、写入报告，并只把数据库文件权限开放给服务账号。

## 上线步骤

1. 上传新的 API 程序，保留旧程序目录。
2. 启动 API。启动入口会先执行只读预检；旧版本数据库需要迁移时，会先创建一致备份，再执行迁移。
3. 预检、备份、迁移或迁移后验证任一步失败时，API 必须退出，不提供半升级服务。
4. 查看启动目录或配置的 `Database:StartupBackupDirectory`：

   - `startup-preflight-*.json`：迁移前检查和备份结果。
   - `*.db`：迁移前一致备份。
   - `startup-verification-*.json`：迁移后结构和业务语义验证结果。
   - `startup-failure-*.json`：迁移失败阶段、版本号和已完成步骤。

5. 确认报告中的 `Passed` 为 `true`，再检查登录、客户列表、订单、授权和设备页面。
6. 重复启动一次 API，确认版本不变、没有重复迁移、没有生成重复数据。

## 失败回滚

1. 停止新 API，保留失败数据库、`startup-failure-*.json`、预检报告和验证报告，不覆盖证据。
2. 找到迁移前生成的 `*.db` 一致备份，校验文件存在且大小不为零。
3. 把当前数据库移到故障目录，把迁移前一致备份恢复到原数据库路径。
4. 删除与恢复数据库同目录的旧 `-wal` 和 `-shm` 文件，避免它们搭配错误数据库。
5. 把恢复后的数据库所有者改回 API 服务账号，确认服务账号可读写。
6. 恢复旧 API 程序目录并启动，检查登录、客户、订单、支付、授权、设备、服务商、佣金、结算、开票和产品页面。

## 中断重试

1. 只有确认失败不是磁盘空间、目录权限或数据库损坏后才能重试。
2. 不得删除迁移前备份和失败报告。
3. 保持同一份数据库和同一份新 API 程序再次启动；迁移步骤按版本和 schema 状态幂等重试。
4. 重复失败时停止重试，回滚到迁移前备份，并把失败报告交给开发排查。

## 人工验收

- [ ] 原有客户登录邮箱、客户号、联系方式、公司名和开票资料可读取。
- [ ] 原有订单号、金额、支付状态、支付时间和退款状态不变。
- [ ] 已下架旧产品仍在历史订单和授权中可解析。
- [ ] 授权到期日、发放原因、设备上限和有效设备状态不变。
- [ ] 服务商等级、佣金比例快照、结算记录和开票关联不变。
- [ ] 重复启动不重复迁移、不重复创建目录数据或管理员。
- [ ] 失败报告包含版本、失败阶段和已完成步骤，不包含客户明细、密码、令牌或云密钥。
