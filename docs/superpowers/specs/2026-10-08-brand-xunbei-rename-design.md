# 品牌更名：用心云·循备 / YxyXb

| 项 | 内容 |
| --- | --- |
| **项目** | 用心云·循备（原「用心云循备」） |
| **状态** | 已批准（头脑风暴 2026-10-08） |
| **范围** | 用户可见品牌文案、默认路径、Doc 改名、服务内部名、命名空间/工程/仓库全面更名为 `YxyXb` |
| **执行策略** | 备份提交 → 分三波次落地 |
| **关联** | 现有 `Doc/用心云·循备-*.md`、`src/Yxy.*`、`Yxy.sln`（实施后将按本表更名） |

---

## 1. 背景与目标

- **注册商标 / 产品商标**：循备。
- **公司既有商标**：用心云（不再单独作为本产品全称）。
- **对外正式全称**：用心云·循备（中间点 `·`，U+00B7）。营销与介绍统一用此全称；「循备」仅作简称，不单独作为窗口/页面主标题。

成功标准见 §7。

---

## 2. 品牌命名规则

| 角色 | 名称 | 用法 |
| --- | --- | --- |
| 注册商标 / 产品商标 | 循备 | 商标与法律文本中的商品名；UI 不单独当窗口标题 |
| 公司既有商标 | 用心云 | 公司品牌；不单独作为本产品全称 |
| 对外正式全称 | 用心云·循备 | 窗口、托盘、邮件主题、官网 title、服务显示名、营销文案 |
| 路径 / 文件系统名 | 用心云循备 | 无点、无空格；默认中文目录、客户标识默认、百度应用文件夹、离线盘目录 |
| 简称 | 循备 | 口头与内部简称 |

替换关系：

- 给人看的全称「用心云循备」→「用心云·循备」。
- 默认文件夹 / 客户标识默认「用心云循备」→「用心云循备」。
- 已装用户旧路径「用心云循备」**不自动迁移**；仅新安装与新默认值使用新名。

## 4. 备份提交与分波次执行

### 4.1 改名前备份（硬门槛）

在开始品牌相关代码/文档修改之前，于主仓库做一次备份提交：

- 建议 message：`chore: backup before brand rename to 用心云·循备 / YxyXb`
- 仅在维护者明确同意「现在提交备份」后执行。
- 提交成功后再进入波次 1。

### 4.2 波次 1 — 品牌与常量（不改命名空间）

- 更新 `AppPaths`（及散落硬编码）中的显示名、路径名、服务显示名、默认 bak 根。
- 客户端、引擎、API 邮件、Web 文案、测试中的「用心云循备」按 §2 / §3 替换。
- `Doc/用心云·循备-*.md` 改名为 `用心云·循备-*.md`，并更新交叉链接与 `docs/superpowers` 引用。
- 验收：仍以 `Yxy.*` 编译通过；相关测试通过。

### 4.3 波次 2 — 服务内部名

- `YxyXbService` → `YxyXbService`。
- 安装/卸载/描述字符串与操作手册「重装服务」说明。
- 验收：本机可删除旧服务、安装新服务，首页引擎操作可用。

### 4.4 波次 3 — 工程与命名空间

- 项目文件夹、`.csproj`、`namespace`、`using`、程序集名 → `YxyXb.*`。
- `Yxy.sln` → `YxyXb.sln`。
- 部署脚本、zip 名、exe 引用同步。
- 工作目录 `yongxinyunbak` → `yxyxb`（含远端时按既有 remote 流程处理）。
- 验收：全量编译与测试；客户端/网站冒烟（登录、标题、一处默认备份路径）。

每波次可回滚到备份点或该波次前一提交；波次之间经确认后再继续。

## 5. 兼容与风险

| 点 | 处理 |
| --- | --- |
| 已装用户目录仍为「用心云循备」 | 不迁移；仅新默认用「用心云循备」 |
| 已装 `yxy.db` | 不自动改名。运行时若 data 目录已有 `yxy.db` 则继续使用，否则新建 `yxyxb.db` |
| 已装 `.yxybackup` marker | 读路径同时识别旧目录名；新写入用 `.yxyxb` |
| 旧 Windows 服务名 | 升级说明：停并删除 `YxyXbService` 后安装 `YxyXbService` |
| 开机启动旧值名 | 新版本写入「用心云·循备」；在开启开机启动时清理或覆盖旧「用心云循备」项 |
| 百度应用文件夹 | 新上传走「用心云循备」；已有网盘数据不搬 |
| 域名与备案 | 主体与 `yongxincloud.cn` 本期不强制变更 |

## 6. 非目标

- 自动搬迁用户旧备份目录或旧百度目录。
- 修改公司主体文案、备案号、客服电话。
- 修改公网域名与证书。
- 建设白标多品牌配置系统。

---

## 7. 验收标准

1. 用户可见「用心云循备」清零（测试夹具中刻意保留旧名的兼容用例除外，且须标注）。
2. 正式全称统一为「用心云·循备」。
3. 新安装默认路径使用「用心云循备」与 `D:\yxyxb\bak`。
4. 服务内部名为 `YxyXbService`，显示名为「用心云·循备 Service」。
5. 解决方案以 `YxyXb.*` 编译，测试通过。
6. Doc 文件名与链接无旧「用心云·循备-」前缀残留（历史 git 提交除外）。

---

## 8. 实施顺序（摘要）

1. 备份提交（§4.1）。
2. 波次 1 → 2 → 3（§4.2–4.4）。
3. 按 §7 做验收；升级说明写入操作手册 / 服务器更新说明。
