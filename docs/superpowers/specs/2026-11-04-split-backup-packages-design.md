# 分卷备份包与运行统计

**日期：** 2026-11-04  
**状态：** 设计已确认，待实现  
**决策：** [ADR-0002](../../adr/0002-split-backup-packages.md)

## 目标

文件备份和数据库备份在生成大型 ZIP 后，按可配置上限拆成多个 ZIP 分卷。所有分卷和清单构成一个备份单元，支持按分卷补传、远端校验、手动下载后自动组装恢复，以及邮件中的文件数、包数和大小统计。

## 不做

- 不在客户端中从七牛、百度、阿里云、腾讯云或天翼云下载备份。
- 不改变七牛和百度现有的 4MB 上传分片、断点续传与重试机制。
- 不修改离线介质任务。离线介质不属于云上传备份包。
- 不覆盖恢复目标目录中的已有文件。

## 已确认规则

1. 先生成完整 ZIP；小于等于上限时保留单 ZIP，超过上限时切成多个有效 ZIP 分卷。
2. 每个分卷内部包含 `manifest.json`；分卷旁另有 `<package>.manifest.json`。外部清单丢失时，恢复工具可读取内嵌清单。
3. 全局默认上限为 `4 GiB`，即 `4294967296` 字节。任务值为 `0` 时继承全局；大于 `0` 时覆盖全局。
4. 完整 ZIP 在全部超限时才会被拆分。分卷和外部清单全部写完并本地校验通过后，才删除完整 ZIP。
5. 发现文件数必须等于成功打包文件数。存在跳过文件时仍尽力生成和上传可读文件，但本次任务最终判定失败。
6. 备份成功只取决于本地包完整性、启用数据通道的上传结果和远端校验。邮件失败显示“备份成功，通知失败”，不把数据备份改成失败。
7. 邮件保留原变量，并新增 `{文件统计}`、`{包统计}`、`{大小统计}`。
8. 自动删除和“上传后立即删本地包”以整个备份单元为单位，统一处理全部分卷与外部清单。

## 备份单元布局

备份目录中的一次超限备份：

```text
<备份目录>/<命名目录>/
├── <package>.zip                      ← 中间完整包，分卷成功后删除
└── <package>.split-<backupId>/
    ├── <package>.manifest.json
    ├── <package>.part01.zip
    ├── <package>.part02.zip
    └── <package>.part03.zip
```

每个分卷是标准 ZIP，内部包含：

```text
payload/<package>.part01.bin
manifest.json
```

`payload/*.bin` 是完整 ZIP 中对应顺序区间的原始字节，不再次压缩。分卷 ZIP 本身使用 store 模式。恢复时按清单顺序连接所有 payload，得到原完整 ZIP。

## 清单格式

外层清单名为 `<package>.manifest.json`。分卷内嵌副本除承载它的分卷最终文件哈希外，其余字段一致；这样避免“哈希写入自身导致哈希变化”的循环依赖。

```json
{
  "FormatVersion": 1,
  "BackupId": "20261104-153000-7f3a2c11",
  "PackageName": "客户A_文件备份_20261104-153000.zip",
  "TaskName": "财务文件",
  "CreatedUtc": "2026-11-04T07:30:00.0000000Z",
  "PartSizeLimitBytes": 4294967296,
  "ArchiveBytes": 10737418240,
  "ArchiveSha256": "大写或小写十六进制 SHA-256",
  "SourceFileCount": 10000,
  "PackedFileCount": 9997,
  "SkippedFileCount": 3,
  "SourceBytes": 41025658880,
  "Parts": [
    {
      "Index": 1,
      "FileName": "客户A_文件备份_20261104-153000.part01.zip",
      "PayloadEntryName": "payload/客户A_文件备份_20261104-153000.part01.bin",
      "PayloadBytes": 4293918720,
      "PayloadSha256": "payload 的 SHA-256",
      "WrappedBytes": 4294965000,
      "WrappedSha256": "分卷 ZIP 文件的 SHA-256"
    }
  ]
}
```

字段规则：

- `FormatVersion` 固定为 `1`，读取时不支持更高版本必须拒绝。
- `BackupId` 在一次备份内唯一，格式为 UTC 时间加 8 位随机十六进制。
- `ArchiveSha256` 是整个完整 ZIP 的 SHA-256。
- `Parts` 按 `Index` 从 1 连续递增。
- `PayloadBytes` 是分卷中的原始字节数；它们的总和必须等于 `ArchiveBytes`。
- `WrappedBytes` 和 `WrappedSha256` 由外层清单记录。内嵌清单允许把自身分卷的这两个字段置为 `0` 和空字符串。
- 不保存压缩密码明文；密码只在恢复时由用户输入或使用当前设置中的密码。

## 分卷算法

1. 用现有 `ZipPacker.Pack` 生成完整 ZIP，并计算大小与 SHA-256。
2. 若 `ArchiveBytes <= PartSizeLimitBytes`，走原单 ZIP 流程，不创建清单。
3. 先生成完整外层清单所需的备份标识、源统计、完整 ZIP 大小与 SHA。
4. 计算每个 payload 区间的偏移、长度和 SHA。分卷包装预留 `1 MiB`，用于内嵌清单和 ZIP 头；因此 payload 上限为 `PartSizeLimitBytes - 1048576`。
5. 第一遍扫描完整 ZIP 计算各 payload SHA；第二遍按偏移读取完整 ZIP，写出每个 store 模式的分卷 ZIP。
6. 分卷完成后计算 `WrappedBytes` 和 `WrappedSha256`，写入外部清单。
7. 重新打开每个分卷，校验 payload 长度和 SHA、内嵌清单、外层清单中的分卷大小和 SHA。
8. 全部通过后删除完整 ZIP。任一步失败时保留完整 ZIP，删除未完成的分卷目录，记录失败。

`PartSizeLimitBytes` 的合法范围为 `64 MiB` 到 `1 TiB`。任务覆盖值超出范围时保存失败；全局值在设置保存时校正到合法范围。

## 运行统计

新增运行统计在扫描源时生成：

```csharp
public sealed class BackupRunStats
{
    public int DiscoveredFiles { get; set; }
    public int PackedFiles { get; set; }
    public int SkippedFiles { get; set; }
    public long SourceBytes { get; set; }
}
```

文件任务的统计来自扩展后的 `SourceWalker`。目录中的文件先计入 `DiscoveredFiles`；可读并进入 ZIP 的文件计入 `PackedFiles` 与 `SourceBytes`；锁定、无权限或读取失败的文件计入 `SkippedFiles`。

数据库任务按数据库名计数：每个选中并成功导出的数据库计为一个打包项目；导出失败的数据库计为跳过项目。源大小使用数据库导出文件的实际字节数，没有导出文件时为 `0`。

日志固定包含：

```text
发现 10000，打包 9997，跳过 3；源 38.2 GB，压缩后 10.0 GB；分卷 3 个。
```

## 上传状态

分卷模式的下发记录为每个本地文件保存独立通道状态：

```csharp
public sealed class PendingUploadFile
{
    public string LocalPath { get; set; }
    public bool NetworkOk { get; set; }
    public bool FtpOk { get; set; }
    public bool CloudOk { get; set; }
}
```

上传顺序固定为全部分卷按序号上传，外部清单最后上传。每个文件成功后立即持久化对应通道状态；重试只补传未成功的文件。单 ZIP 继续使用原有 `ZipPath`、`NetworkOk`、`FtpOk`、`CloudOk`，保持历史记录兼容。

远端校验规则：

- UNC/FTP：确认目标文件存在且长度等于本地文件长度。
- 七牛、百度、阿里云、腾讯云、天翼云：上传后查询远端对象，确认存在且长度等于本地文件长度。
- 云提供商返回可比较的 MD5 或对象校验值时，与本地摘要比较；返回的是服务商专用 ETag 时，记录该值并要求非空，同时以本地分卷 SHA-256 校验作为内容证据。
- 任一启用通道仍有未成功文件时，数据状态为失败；重试从首次失败阶段继续。

## 完成判定

| 条件 | 任务状态 | 邮件 | 本地包 |
| --- | --- | --- | --- |
| 无跳过文件，所有启用数据通道校验成功，邮件成功 | 成功 | 发送成功 | 可按现有规则保留或立即删除 |
| 无跳过文件，所有启用数据通道校验成功，邮件失败 | 成功 | 显示“备份成功，通知失败” | 可以立即删除；通知失败不阻断数据完成 |
| 有跳过文件，但可读文件的上传与校验成功 | 失败 | 发送失败统计 | 保留，等待下次重试 |
| 任一启用通道有分卷或清单未成功 | 失败 | 发送失败统计 | 保留，下轮只补未成功项 |

任务成功时仍进入下一轮计划；失败时使用现有 `retry_minutes`。日志结果增加 `warn`，用于表达数据成功但通知失败；任务调度只按数据成败决定。

## 邮件变量

新增三个变量，并保留 `{任务}`、`{结果}`、`{时间}`、`{详情}`、`{客户标识}`：

- `{文件统计}`：`发现 10000，打包 9997，跳过 3`
- `{包统计}`：`共 3 个分卷，上传成功 3/3`
- `{大小统计}`：`源 38.2 GB，压缩后 10.0 GB，已上传 10.0 GB`

数据库任务把“发现/打包/跳过”替换为“数据库/导出/跳过”，其余格式保持一致。人工测试邮件使用空统计值。

## 手动下载与恢复

本期不提供云空间下载。恢复流程：

1. 用户从云空间手动下载同一次备份的全部分卷和外部清单。
2. 将文件放在同一个本地目录。
3. 在“实例恢复”页新增的“文件”页签中选择该目录。
4. 选择恢复目录；程序在恢复目录下新建 `restore-yyyyMMdd-HHmmss` 子目录。
5. 程序扫描目录，只允许找到一组 `BackupId`。若有多组、缺卷、重复卷或清单不一致，拒绝开始。
6. 优先读取外部清单；缺失时读取任一已下载分卷中的内嵌清单。
7. 校验分卷文件大小和 SHA-256，按顺序拼接 payload 到临时完整 ZIP，并校验 `ArchiveSha256`。
8. 安全解压该 ZIP 到新建子目录。拒绝 `../`、绝对路径和越过目标目录的条目。
9. 删除临时组装 ZIP。

恢复目录非空时仍允许，因为实际写入的是新建的时间戳子目录；如果同名时间戳目录已存在，追加 `-01`、`-02`。

MSSQL/MySQL 分卷恢复复用同一组装器：先在临时目录得到完整 ZIP，再交给现有 `ExtractFirst` 和数据库恢复逻辑。一个分卷目录只放一组数据库备份。

## 存储与配置

`settings` 增加：

```sql
part_size_bytes INTEGER NOT NULL DEFAULT 4294967296
```

`file_tasks`、`mssql_tasks`、`mysql_tasks` 各增加：

```sql
part_size_bytes INTEGER NOT NULL DEFAULT 0
```

`AppSettingsDto.PartSizeBytes` 保存全局值；三个任务 DTO 的 `PartSizeBytes` 为 `0` 表示继承，大于 `0` 表示覆盖。详细、任务编辑和数据库设置都需要读写该字段。

`PendingRecord` 增加 `BackupId`、`RunStats` 和可空的 `UploadFiles`。旧 `pending_json` 没有这些字段时按单 ZIP 历史记录解析，不丢弃原记录。

## 远端对象与清理

分卷对象放在同一个产品前缀和同一任务目录下，并使用独立备份目录：

```text
<客户标识>/<file|mssql|mysql>/<任务名>/<package>.split-<backupId>/
```

外部清单名为 `<package>.manifest.json`。单 ZIP 继续使用现有 `CloudObjectKeys.ForZip`，保持旧包可清理。

自动删除按备份单元执行：

1. 找到外部清单及同目录下的全部分卷。
2. 只有整个单元都超过保留天数时才删除。
3. 删除时先删分卷，最后删外部清单；删除清单失败时下次重试。
4. 本机、UNC、FTP 和每个云提供商分别执行。云提供商不支持原子删除，失败时记录完整日志，不把部分删除报告为全部成功。
5. “上传后立即删本地”同时清理完整 ZIP、分卷目录和外部清单。

## 兼容性

- 未超限的单 ZIP、已有 `pending_json` 和已经上传的历史单 ZIP 继续按原逻辑处理。
- 新的分卷记录使用同一 `pending_json` 字段，不新增数据库表。
- 旧客户端不识别分卷目录；升级后由新客户端负责上传、恢复和清理。
- 远端清单格式版本不支持时拒绝恢复，不猜测字段。

## 验收

- 10 GiB ZIP 在 4 GiB 上限下生成 3 个分卷，每个分卷文件不超过配置上限。
- 删除或损坏任一 payload 后恢复拒绝，并指出缺失或哈希不一致的分卷。
- 用户把全部分卷和外部清单放入一个目录后，选择该目录即可恢复出原始目录结构。
- 外部清单丢失但内嵌清单存在时仍可恢复。
- 10000 个源文件、3 个无法读取时，任务失败且邮件显示发现、打包、跳过数量。
- 三个分卷依次上传，第二个失败，下一轮只补传第二个、第三个和外部清单尚未成功的通道。
- 所有启用数据通道校验成功但邮件失败时，备份状态为成功、通知状态为失败。
- 自动删除只删除完整备份单元，不留下孤儿分卷或清单位置。
