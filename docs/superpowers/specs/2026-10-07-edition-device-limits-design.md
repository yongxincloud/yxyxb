## 1. 目标

把授权从「一账号不限台数」改为三个正式版本，**本期仅差设备上限与价格**，功能能力相同。

| 版本 | ProductNo（种子） | 默认 MaxDevices | 默认原价（元/年） |
| --- | --- | --- | --- |
| 个人版 | `PERSONAL` | 3 | 36 |
| 标准版 | `STANDARD` | 10 | 98 |
| 专业版 | `PRO` | 50 | 198 |

- 厂商后台可改：**原价、促销价与窗口、MaxDevices、上下架、排序**。
- 无线上付费存量：不做「legacy 不限台」兼容；种子直接切三档（原单一 `STD` 由迁移/种子替换为三档）。
- 试用不限设备；正式订阅才按当前授权产品的 `MaxDevices` 限台。

成功标准见 §7。

---

## 2. 架构

采用 **扩展现有产品 + 客户端鉴权**（单体 `Yxy.Api`），不新增独立授权微服务。

```text
Yxy.Web                         Yxy.Api
├── 首页定价三列                   ├── Products（三档 + 价/促销/MaxDevices）
├── 门户：订阅 / 升级 / 我的设备   ├── Orders（新购 / 续费 / 升级补差）
├── 厂商：产品定价与促销           ├── AccountDevices（占坑 / 踢出）
└── 客户端：登录占坑 / 设备管理     └── ClientAuth（登录占坑或 DEVICE_LIMIT）
```

**改动边界：** API、Web 首页/门户/厂商产品、客户端登录与设备管理。不改备份 / 离线介质业务逻辑。

---

## 3. 设备占用规则

| 规则 | 口径 |
| --- | --- |
| 何为设备 | 客户端带上的稳定 `deviceId`；一台电脑登录占一坑 |
| 占坑 | 正式授权下首次登录写入占用；同机重登复用同一坑，更新 `LastSeenAt` |
| 退出登录 | **不释放**名额 |
| 释放 | 用户在 **门户或客户端** 主动踢出 |
| 踢出效果 | 该 `deviceId` 下会话 token **立即作废** |
| 试用 | 不强制设备上限 |
| 空 deviceId | 登录拒绝（正式与试用均要求有标识） |

满员时新设备登录失败，引导：**踢出旧设备** 或 **升级更高档**。

后台将某产品 `MaxDevices` 调小时：**不自动踢设备**。超员账号不能再登记新设备；已占用设备可继续 verify，直到用户自行踢到合规。

## 4. 数据模型

### 4.1 `Products` 扩展

| 字段 | 说明 |
| --- | --- |
| `Price` | 原价 |
| `PromoPrice` | 促销价，可空 |
| `PromoStart` / `PromoEnd` | 促销窗口；有促销价时起止必填且 Start &lt; End |
| `MaxDevices` | 最大设备数，后台可改 |
| `SortOrder` | 营销页列顺序 |
| 既有 | `ProductNo`、`Name`、`Description`、`PeriodDays`（正式仍 365）、`Status` |

**现价：** 若当前时间在促销窗内且 `PromoPrice` 有值 → 用促销价，否则用原价。

### 4.2 新表 `AccountDevices`

| 字段 | 说明 |
| --- | --- |
| `AccountId` + `DeviceId` | 唯一 |
| `DisplayName` | 展示名；客户端登录上报，格式 `电脑名 · MAC · Windows用户` |
| `FirstSeenAt` / `LastSeenAt` | 首次占坑 / 最近活动 |
| `Status` | 1=占用，0=已踢出 |
| `KickedAt` | 踢出时间，可空 |

### 4.3 订单与授权

- 订单类型：`1=正式`、`2=试用`、`3=升级补差`。
- 升级支付成功：当前有效 `SubscriptionAuth.ProductId` 改为新产品；**`AuthEndTime` 不变**；设备上限立即按新档。
- 订单金额仍快照；改价/促销只影响之后新单。
- 续费可选任意在售档（含降档）；周期在原到期日上 +365。

替换种子：去掉（或下架）单一 `STD`，写入 `PERSONAL` / `STANDARD` / `PRO`。

## 5. 商务规则

### 5.1 升级（周期内）

- 仅允许升到 `MaxDevices` 更大的在售档。
- 金额 = `剩余整天数 × (新档现价 − 旧档现价) / 365`，保留两位小数；若结果 ≤ 0 则拒绝升级单。
- 到期日不变；设备全部保留。

### 5.2 降级

- **仅到期续费时可降**；周期内不可降、不退差价。
- 若当前占用数 &gt; 新档 `MaxDevices`，续费前必须先踢到合规。

### 5.3 促销

- 日常可改原价；另可设每档促销价 + 起止时间。
- 营销页展示原价（可划线）与现价；促销结束自动回原价。
- 佣金 = 订单金额 × 等级比例快照，自动适配任意价。

### 5.4 试用转正

- 试用期间不限台，可不写入占用或写入但不强制上限。
- 首次正式订单支付成功后，授权绑定所选档；自该时刻起按 `MaxDevices` 限台。
- **占坑时机：** 各设备在转正后的下一次登录/verify 时再占坑；先到先得，占满后其余设备得 `DEVICE_LIMIT`，须踢出后再登。
- **宽限期（grace）：** 与正式有效期相同，仍按当前产品 `MaxDevices` 限台。

## 6. 接口与界面（要点）

### 6.1 公开价目

`GET /api/public/price` 改为返回 `{ plans: [...] }`（无线上依赖方可破坏性变更）：每项含 `productNo`、`name`、`maxDevices`、`listPrice`、`salePrice`、`promoActive`、`promoEnd`、`sortOrder`。只含上架产品，按 `sortOrder` 排序。

首页 **一页三列** 绑定 `plans`，价格与上限不得写死。

### 6.2 客户端鉴权

登录 / verify：

- 试用：发 token，不强制上限。
- 正式：已占用则刷新 `LastSeenAt`；未占用且未满则占坑；满员 → 业务码 `DEVICE_LIMIT`（建议 HTTP 409），附 `maxDevices`、设备摘要、可升级产品提示。
- 会话增加：`productNo`、`maxDevices`、`deviceCount`（或等价字段）。

### 6.3 设备管理

- 门户与客户端：`GET` 设备列表、`POST/DELETE` 踢出。
- 允许踢本机（确认后强制重新登录占坑），避免锁死。

### 6.4 厂商后台

- 产品页：改原价、促销价/窗口、`MaxDevices`、上下架、排序；改价/促销写 `operation_log`。
- 发放授权时可选三档之一。

### 6.5 门户购买 / 升级

- 新购选档下单；升级走预览差价 → 下单支付。
- 续费选档；降档前校验设备数。

## 7. 错误与验收

| 场景 | 行为 |
| --- | --- |
| 满员登录 | `DEVICE_LIMIT`，引导踢设备或升级 |
| 被踢后 verify | token 无效，客户端清登录态 |
| 升级目标不高于当前档 | 拒绝 |
| 促销窗口非法 | 保存拒绝 |
| `MaxDevices` 调小导致超员 | 不自动踢；禁新坑直至用户踢合规 |

**必测**

1. 公开价目与促销过期回原价  
2. 后台改价 / MaxDevices / 促销后营销页与新单正确  
3. 个人版 3 台满员与踢出后再登  
4. 退出不释放；同机重登不占新坑  
5. 门户与客户端均可踢；踢后 token 失效  
6. 升级补差金额与到期日不变、上限立刻变  
7. 续费降档超员拦截  
8. 试用不限台；转正后限台  
9. 订单金额快照不随后台改价变化  
10. 佣金按订单金额计算  

**本期不做：** 功能分档、优惠码、周期内降级退款、旧不限台兼容。
