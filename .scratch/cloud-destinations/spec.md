## Problem Statement

客户使用七牛云、百度网盘、阿里云、腾讯云和天翼云保存备份包。当前上传后的远端校验和过期清理顺序分散在云 runtime、Core 和五家 adapter 中：同一份“分卷先删、清单最后删、失败立即停止”规则被复制五次，日志接入依赖具体 adapter 类型，过期判断还会把同一目录下不属于同一备份单元的 ZIP 混在一起。

## Solution

把云去向收拢为一个深 module。调用者只提交本地文件、对象名、保留时间或清理前缀；module 内部完成上传恢复、远端大小校验、分页对象归类、整组过期判断和清单最后删除。五家 adapter 只保留签名、HTTPS 请求、分页协议和单次删除调用差异。

## User Stories

1. 作为云备份用户，我希望上传中断后远端已有完整对象时复用该对象，以便不重复上传大包。
2. 作为云备份用户，我希望上传返回异常但远端对象大小匹配时继续成功，以便网络抖动不产生重复包。
3. 作为云备份用户，我希望上传成功后再次校验远端大小，以便不把空文件或残缺对象报告为成功。
4. 作为七牛云、阿里云、腾讯云和天翼云用户，我希望分卷删除顺序一致，以便清单不会先于分卷消失。
5. 作为百度网盘用户，我希望整组删除使用同一单元规则，而不是递归删除目录。
6. 作为云备份用户，我希望任一文件过期判断不通过时整组保留，以便历史备份不会只删一半。
7. 作为云备份用户，我希望分卷删除失败时立即停止且清单保留，以便下次清理仍有证据。
8. 作为云备份用户，我希望旧的单 ZIP 仍按保留时间删除，以便历史对象不会永久残留。
9. 作为维护者，我希望清理前缀为空或不属于产品前缀时停止，以便绝不清理客户其它对象。
10. 作为维护者，我希望五家 adapter 共用一组 fake 测试，以便不依赖真实云账号即可回归高风险顺序。

## Implementation Decisions

- 保持 `ICloudStorage` 为五家云唯一的协议 seam；签名、HTTPS、分页和协议错误映射留在 adapter。
- 上传入口内部完成“远端存在则校验、上传异常后复核、上传成功后校验”，调用者不再单独执行第二次远端校验。
- 日志 sink 提升到 `ICloudStorage`，runtime 不再按具体 adapter 类型重复接线。
- 新增 Core 内的云对象目录 adapter 和云清理 module；目录 module 只负责返回对象键与 UTC 修改时间。
- 清理 module 按清单文件名和分卷文件名推导同一备份单元，不再按目录合并所有 ZIP。
- 一个备份单元只有在清单和全部分卷都可确定、时间均早于保留时点时才过期。
- 删除顺序固定为分卷在前、清单最后；失败立即抛出，不继续删除后续单元或清单。
- 没有清单的独立旧 ZIP 可按保留时间删除；缺少清单的孤立分卷保留，交人工处理。
- 产品前缀为空时拒绝执行，所有待删对象必须再次验证以产品前缀开头。
- 不改变对象命名、分片算法、分卷格式、上传限速或五个 cloud provider key。

## Testing Decisions

- 测试从 `ICloudRuntime` 的上传行为开始，使用 fake `ICloudStorage` 验证复用、异常复核、成功后校验和大小不一致失败。
- 清理测试使用 fake 云对象目录，验证同目录多单元隔离、分卷先于清单、任一文件未过期则整组保留、失败中止、单 ZIP 和孤立分卷处理。
- 前缀安全测试验证空前缀拒绝以及前缀外对象永不进入删除批次。
- adapter 迁移后运行现有 solution 测试和新增聚焦测试；不连接真实云账号，不读取本地云凭据。

## Out of Scope

- 新增云服务商、空间下载、增量备份、去重或版本浏览。
- 修改对象命名、分片大小、限速策略或百度授权流程。
- 清理线上历史孤儿对象或改写已有备份记录。

## Further Notes

用户已人工验证七牛云和百度网盘现有上传可用。本阶段只深化本地调用链，不执行真实云删除。
