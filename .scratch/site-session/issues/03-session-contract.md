# 03: 清理旧静态登录实现并冻结兼容矩阵

**Parent:** [架构深化与存量数据安全](../../architecture-deepening/spec.md)

**What to build:** 在登录和设备路径都已迁移后，删除重复的 static 网站会话实现和正则 JSON 解析，让 WPF 只保留 UI adapter。通过完整兼容矩阵确认旧会话、断网、设备上限和换机重登行为没有退化。

**Blocked by:** 02 - 迁移设备会话与我的设备页

**Status:** ready-for-agent

- [ ] 生产调用方不再使用旧的独立 HTTP 登录、正则解析或重复 session 写入路径。
- [ ] 旧格式的 token/session 文件仍可读取，升级不会要求未受影响客户重新登录。
- [ ] WPF 登录窗口只负责输入、提示和调用网站会话 module，不持有协议解析或持久化规则。
- [ ] 密码登录、验证码登录、设备上限、断网宽限、被踢出、换机重登和会话损坏矩阵全部通过。
- [ ] 网站会话 module 的测试工程加入 solution，solution 构建成功且无新增警告。
- [ ] 兼容测试夹具不包含真实客户邮箱、token、设备标识或网站凭据。
- [ ] 本 ticket 不连接或修改生产服务器，不改变网站 API 契约或数据库结构。
