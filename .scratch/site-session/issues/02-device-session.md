# 02: 迁移设备会话与我的设备页

**Parent:** [架构深化与存量数据安全](../../architecture-deepening/spec.md)

**What to build:** 将启动时会话校验、设备一致性检查、设备列表、踢出设备和设备上下文上报迁移到 Ticket 01 建立的网站会话 module。客户端“我的设备”页面和后台设备记录继续按现有人机边界工作。

**Blocked by:** 01 - 网站会话模块接管登录

**Status:** ready-for-agent

- [ ] 启动时可使用新 module 验证 token，并在设备被踢出、设备换机或账号失效时要求重新登录。
- [ ] 网络不可达时继续沿用现有离线宽限策略，不因短暂网络故障清除有效会话。
- [ ] 设备列表返回设备标识、显示名、首次/最近使用时间和当前设备标记。
- [ ] 踢出设备成功后，本机或其他设备失效行为与现有 token 作废规则一致。
- [ ] 客户标识和当前任务状态作为设备上下文上报，内容与现有规则一致。
- [ ] “我的设备”页面的查看、刷新、踢出和错误提示保持现有可见行为。
- [ ] 测试使用 fake HTTP、临时 session/token 文件和临时 SQLite，覆盖有效会话、网络不可达、被踢出、换机和设备列表。
- [ ] 本 ticket 不删除旧静态登录 public 入口，直到 Ticket 03 完成兼容验收。
