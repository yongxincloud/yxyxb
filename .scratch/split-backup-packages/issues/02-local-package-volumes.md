# 可配置分卷上限与本地分卷清单

Category: enhancement  
Status: ready-for-agent  
Type: AFK

## Parent

[分卷备份包与运行统计](../spec.md)

## What to build

设置页提供默认 4 GiB 的全局分卷上限，文件任务可继承或覆盖。文件备份先生成完整 ZIP；超过上限时按字节切成多个有效 ZIP 分卷，生成外部清单和每卷内嵌清单，并将分卷上传到当前启用的数据通道。此切片先提供完整的一次性上传结果，逐卷续传和远端校验由后续工单增强。

## Acceptance criteria

- [ ] 全局默认值为 4 GiB，合法范围为 64 MiB 到 1 TiB。
- [ ] 文件任务保存 0 表示继承，正数表示覆盖，重新打开后值保持一致。
- [ ] 未超限的备份继续产生单个 ZIP。
- [ ] 超限备份生成 `<package>.manifest.json` 和有序 `partNN.zip` 分卷。
- [ ] 每个分卷是有效 ZIP，内含 payload 和内嵌 `manifest.json`。
- [ ] 全部分卷及清单校验通过后删除完整 ZIP。
- [ ] 当前启用的网络共享、FTP 和云通道可以上传分卷与清单。
- [ ] 缺少、重复或损坏分卷时任务失败，不产生错误的成功状态。

## Agent Brief

**Category:** enhancement  
**Summary:** 为文件备份增加可配置的分卷上限，并在完整 ZIP 超限时生成可由清单恢复的独立 ZIP 分卷。

**Current behavior:**

设置只包含备份目录、压缩等级和压缩密码。文件备份使用单 ZIP 方案：所有可读文件直接写入一个 ZIP，待传记录只保存这个 ZIP 的路径。上传通道按一个包处理，没有分卷上限、分卷清单、内嵌清单或分卷组装能力。

**Desired behavior:**

设置页提供全局分卷上限，默认 4 GiB，合法范围为 64 MiB 到 1 TiB。文件任务可以选择继承全局值或使用自己的正数覆盖值。任务值为 0 表示继承。

文件扫描和完整 ZIP 生成沿用现有流程。完整 ZIP 未超过解析后的上限时继续使用单 ZIP。超过上限时，按原始字节顺序切成多个有效 ZIP 分卷；每个分卷包含一个 store 模式 payload 和一份内嵌清单，分卷旁另存一份外部清单。

清单记录格式版本、唯一备份标识、包名、任务名、创建时间、分卷上限、完整 ZIP 大小和 SHA-256、文件数量、源大小，以及每个分卷的序号、payload 名称和大小、payload SHA-256、分卷文件大小和 SHA-256。内嵌清单省略承载它的分卷最终包装哈希，避免自引用。

全部分卷和外部清单在本地写入并通过校验后，删除完整 ZIP 中间文件。当前启用的网络共享、FTP 和云通道可以上传全部分卷与外部清单；本工单按通道记录整个备份单元的一次性成功状态，暂不实现逐文件续传和远端内容校验。

任何缺失、重复、版本不支持、payload 长度不一致或哈希不一致的分卷都必须使任务失败，不能产生成功结果。

**Key interfaces:**

- `PackageLimits`：负责默认值、合法范围、全局值规范化和任务值 `0=继承` 的解析。
- `BackupPackageManifest`：描述完整 ZIP、运行数量、分卷顺序、大小和哈希。
- `PackageSplitter.Split()`：输入完整 ZIP、任务名、分卷上限和运行统计；未超限时不拆卷，超限时返回分卷目录、外部清单和有序分卷路径。
- `AppSettingsDto` 和 `FileTaskDto`：增加分卷上限字段；设置与任务存储负责持久化和旧库迁移。
- 设置页与文件任务编辑入口：提供 GiB 输入；0 表示跟随全局。
- 待传记录：保存分卷目录、外部清单和全部分卷路径，使当前单 ZIP 的上传流程能够遍历备份单元。
- 现有网络共享、FTP 和云上传接口：保留现有单文件上传能力，由任务执行层按分卷顺序调用。

**Acceptance criteria:**

- [ ] 全局分卷上限默认 4 GiB，输入低于 64 MiB 或高于 1 TiB 时被拒绝或规范化。
- [ ] 文件任务值为 0 时使用全局值，正数时覆盖全局值，保存并重新打开后保持一致。
- [ ] 完整 ZIP 小于等于上限时仍产生单个 ZIP，不要求清单。
- [ ] 完整 ZIP 超过上限时生成多个有序 `<package>.partNN.zip` 分卷和外部 `<package>.manifest.json`。
- [ ] 每个分卷是有效 ZIP，包含对应原始字节 payload 和一份内嵌 `manifest.json`。
- [ ] 内嵌清单与外部清单一致，仅承载它的分卷最终包装大小和哈希被省略。
- [ ] 全部分卷和外部清单通过本地校验后才删除完整 ZIP。
- [ ] 当前启用的网络共享、FTP 和云通道能够上传全部分卷，最后上传外部清单。
- [ ] 缺少、重复、版本不支持、payload 总长度不一致或任一哈希不一致时任务失败。
- [ ] 失败时保留可诊断的完整 ZIP 或已生成分卷，不把残缺备份单元报告为成功。
- [ ] 单 ZIP 和历史待传记录保持兼容。
- [ ] 文件级测试验证未超限、超限多卷、缺卷和损坏分卷；任务执行测试验证配置继承与当前启用通道的基础上传。

**Out of scope:**

- 逐文件、逐通道续传和远端对象校验；这些由后续上传增强工单负责。
- 手工目录恢复、MSSQL/MySQL 分卷和整单元自动删除。
- 标准 `.z01`/`.z02`/`.zip` 分卷格式和 Windows 资源管理器自动组装。
- 修改七牛、百度的 4MB 上传分片或断点续传算法。
- 真实云账号验收和凭证操作。
- 恢复当前工作树中无关的已删除测试或部署文件。
