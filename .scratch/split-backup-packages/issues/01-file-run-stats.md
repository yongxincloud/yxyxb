# 文件统计、严格失败与邮件变量

Category: enhancement  
Status: ready-for-agent  
Type: AFK

## Parent

[分卷备份包与运行统计](../spec.md)

## What to build

文件备份任务在扫描源目录时记录发现文件数、打包文件数、跳过文件数和源数据大小。存在跳过文件时仍处理可读文件并尽力完成上传，但任务最终判定失败。日志、结果和邮件显示本次统计，并新增 `{文件统计}`、`{包统计}`、`{大小统计}` 三个变量。

## Acceptance criteria

- [ ] 扫描结果区分发现、可打包、跳过文件和源字节数。
- [ ] 锁定、无权限或读取失败的文件进入跳过数量，并保留可诊断路径。
- [ ] 跳过数大于零时任务失败，但可读文件仍继续执行。
- [ ] 日志显示发现、打包、跳过数量和源数据大小。
- [ ] 邮件新增三个统计变量，原有五个变量保持兼容。
- [ ] 邮件失败单独记录为通知失败，不把所有情况都误报为数据失败。
- [ ] 任务执行层测试覆盖完整成功、存在跳过文件和邮件失败三种结果。

## Agent Brief

**Category:** enhancement  
**Summary:** 为文件备份记录准确的运行统计，并把跳过文件、数据上传和邮件通知分别判定。

**Current behavior:**

文件扫描只返回可打包文件列表和一个混合的跳过路径列表。任务日志记录可打包数量与跳过路径数量，但没有可靠的“发现文件总数”，也不会计算成功读取文件的总字节数。存在无法读取的文件时，任务仍可能被判定成功。

邮件模板只支持 `{任务}`、`{结果}`、`{时间}`、`{详情}`、`{客户标识}`。邮件发送失败会使当前任务整体失败，日志只有成功和失败两种结果。

**Desired behavior:**

扫描一次文件备份源，同时产生可打包文件、跳过文件诊断和运行统计。发现文件数必须等于打包文件数加文件跳过数；目录级扫描错误单独保留为诊断，不伪装成文件数量。

存在一个或多个文件被跳过时，仍为可读文件生成备份包并执行当前启用的数据上传，但数据状态必须为失败，本地包和未完成上传记录保留以供重试。只有跳过数为零，且当前启用的数据通道全部成功时，数据状态才为成功。

邮件成功与否独立于数据状态：

- 数据成功且邮件成功：任务成功，结果正常。
- 数据成功但邮件失败：任务仍按数据成功进入下一轮，结果记录为警告。
- 数据失败：任务失败，并按现有重试间隔重试。

日志和邮件展示本次发现、打包、跳过数量；单 ZIP 场景展示包数以及源大小、压缩后大小和已上传大小。原有邮件变量和已有用户模板保持不变。

**Key interfaces:**

- `SourceWalker`：保留现有可打包文件结果，同时提供发现文件数、文件跳过数、诊断路径和源字节数。
- `BackupRunStats`：包含 `DiscoveredFiles`、`PackedFiles`、`SkippedFiles`、`SourceBytes`，由扫描阶段填充。
- `FileBackupRunner`：根据文件完整性和启用数据通道产生数据成功/失败状态；不得因为邮件失败把数据备份标记为失败。
- `MailRunStats`：包含文件统计、包统计和大小统计的可渲染文本。
- `MailUtil`：接受可选运行统计，并在原模板变量之后替换三个新变量。
- 日志结果：增加 `warn` 语义，用于数据成功但通知失败；现有 `ok` 和 `error` 保持兼容。

**Acceptance criteria:**

- [ ] 源目录中的普通文件计入发现数；成功读取并进入备份包的文件计入打包数和源字节数。
- [ ] 锁定、无权限或读取失败的文件计入跳过数并保留可诊断路径。
- [ ] 发现文件数等于打包文件数加文件跳过数。
- [ ] 目录级扫描失败单独记录，不计成文件跳过数。
- [ ] 跳过数大于零时，任务失败，但可读文件仍完成打包和当前启用的上传尝试。
- [ ] 跳过文件导致失败时保留本地备份包和待传记录，供后续重试。
- [ ] 日志显示发现、打包、跳过和源数据大小。
- [ ] 邮件支持 `{文件统计}`，输出发现、打包、跳过数量。
- [ ] 邮件支持 `{包统计}`，单 ZIP 时显示当前包数和成功上传数。
- [ ] 邮件支持 `{大小统计}`，输出源大小、压缩后大小和已上传大小。
- [ ] 原有五个邮件变量继续工作，未配置新变量时默认模板保持可读。
- [ ] 数据成功但邮件失败时记录警告，并按数据成功进入下一轮计划。
- [ ] 任务执行层测试覆盖完整成功、存在跳过文件和邮件失败三种外部行为。

**Out of scope:**

- 分卷生成、分卷上传、分卷恢复和分卷清理。
- MSSQL、MySQL 和离线介质任务的运行统计改造。
- 新增 WPF 页面或引入 WPF 自动化测试框架。
- 修改 SMTP 配置字段或邮件发送协议。
- 恢复当前工作树中无关的已删除测试和部署文件。
