# 分卷上传、远端校验与逐卷补传

Category: enhancement  
Status: ready-for-agent  
Type: AFK

## Parent

## What to build

分卷备份按文件记录网络共享、FTP 和云通道是否成功。上传顺序为全部分卷后外部清单，失败重试只补传未完成文件和通道。每个通道完成上传后验证对象存在和大小；云服务商返回摘要时记录并校验摘要，返回专用 ETag 时记录该值并以本地 SHA-256 作为内容证据。

## Acceptance criteria

- [ ] 待传记录保存每个分卷和清单的独立通道状态。
- [ ] 重试不会重复上传此前已成功的文件或通道。
- [ ] 外部清单在全部数据分卷之后上传。
- [ ] 远端对象不存在或大小不一致时该通道不判定成功。
- [ ] 所有启用通道的全部分卷和清单校验成功后才判定备份成功。
- [ ] 历史单 ZIP 待传记录仍可读取和继续。
- [ ] 测试用假通道覆盖中途失败、部分成功、整卷补齐和校验失败。

## Agent Brief

**Category:** enhancement  
**Summary:** 为分卷备份记录逐文件和逐通道上传状态，验证远端对象，并只补传未完成的文件和通道。

**Current behavior:**

待传记录只有整个备份包的 `NetworkOk`、`FtpOk`、`CloudOk` 三个布尔值，上传函数一次只处理一个 ZIP。某个通道失败后，下一次只能把整个通道重新执行。上传成功只依赖上传调用未抛异常，没有统一查询远端对象是否存在、大小是否一致或摘要是否可用。

现有历史记录都指向单个 ZIP。七牛和百度仍保留各自的 4MB 上传分片和断点续传能力，但这些分片发生在单个文件内部，与备份包分卷不是同一个概念。

**Desired behavior:**

分卷备份单元在待传记录中保存每个本地文件的路径，以及该文件在网络共享、FTP、云三个通道上的独立成功状态。外部清单也作为一个上传文件记录，并始终排在全部数据分卷之后。

每次执行只上传尚未成功的文件与通道，已成功的组合不得重复上传。单个文件上传后立即持久化该文件对应通道的结果，进程中断后再次运行可以沿用已记录的成功项。

每个通道完成上传后执行远端校验：

- 网络共享和 FTP 确认目标文件存在，长度与本地文件一致。
- 云通道确认远端对象存在，长度与本地文件一致。
- 云服务商提供可比较摘要时，比较远端摘要和本地摘要。
- 只提供专用 ETag 时，记录 ETag 并要求非空，同时使用本地 SHA-256 校验分卷内容。

只有全部启用通道的全部数据分卷和外部清单都通过校验，整次数据上传才成功。任一文件或通道仍有未完成项时，任务失败并保留备份单元，下一次只补传缺失项。

历史单 ZIP 记录没有逐文件状态时，继续使用原有整包通道状态，不能因为反序列化新增字段而失效。

**Key interfaces:**

- `PendingUploadFile`：保存本地路径，以及网络共享、FTP、云通道的独立完成状态。
- `PendingItem`：为分卷模式保存有序上传文件集合，同时保留单 ZIP 历史字段。
- `PendingBackup`：根据所有文件状态聚合每个通道是否仍需发送；旧记录继续按整包状态判断。
- `PendingFiles`：按数据分卷、外部清单的顺序遍历，只调用仍需发送的文件通道，并在每个文件成功后触发持久化。
- `ICloudStorage` 或等价云接口：增加远端对象查询，返回对象大小、可比较摘要和摘要类型。
- `ICloudRuntime`：提供本地文件与远端对象的一致校验，使任务层不依赖具体云服务商。
- 网络共享和 FTP：增加远端长度检查，成功上传但远端缺失或长度不一致时返回失败。

**Acceptance criteria:**

- [ ] 分卷待传记录为每个分卷和外部清单保存独立的三通道状态。
- [ ] 上传顺序始终是全部分卷按序号完成后才上传外部清单。
- [ ] 只补传尚未成功的文件和通道，已成功组合不会重复上传。
- [ ] 上传过程中每完成一个文件与通道组合后立即保存状态。
- [ ] 网络共享或 FTP 远端文件缺失、长度不一致时不记录该通道成功。
- [ ] 云对象缺失、长度不一致，或可比较摘要不一致时不记录云通道成功。
- [ ] 专用 ETag 被记录且非空，本地 SHA-256 仍能验证分卷内容。
- [ ] 所有启用通道的全部分卷和外部清单都通过校验后，数据上传才判定成功。
- [ ] 部分成功时保留备份单元和逐文件状态，下一轮只补失败项。
- [ ] 历史单 ZIP 待传记录可以继续读取、上传和判定成功。
- [ ] 假通道测试覆盖第二卷中途失败、部分通道成功、后续补齐和远端校验失败。
- [ ] 不连接真实云账号或真实 FTP 的自动化测试可以完整验证本工单行为。

**Out of scope:**

- 分卷生成、清单创建、配置界面和基础一次性上传；这些由工单 02 提供。
- 手工目录恢复、MSSQL/MySQL 分卷和整单元自动删除。
- 修改七牛、百度的 4MB 上传分片、断点续传、并行数或限速算法。
- 使用真实云账号或凭证完成验收。
- 标准 `.z01`/`.z02`/`.zip` 分卷格式。
- 恢复当前工作树中无关的已删除测试或部署文件。
