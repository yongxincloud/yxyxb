# MSSQL/MySQL 分卷与目录恢复

Category: enhancement  
Status: ready-for-agent

## Parent

## What to build

MSSQL 和 MySQL 备份使用与文件备份相同的分卷上限、清单、上传校验和手动目录恢复规则。每个数据库备份包独立形成完整 ZIP 或分卷单元；恢复时先组装目录中的备份单元，再复用现有数据库恢复流程。

## Acceptance criteria

- [ ] MSSQL 和 MySQL 任务支持继承或覆盖分卷上限。
- [ ] 每个成功导出的数据库 ZIP 超过上限时生成独立分卷单元。
- [ ] 数据库任务邮件显示数据库、导出、跳过数量。
- [ ] 数据库恢复页支持选择单 ZIP 或分卷目录。
- [ ] 分卷目录只允许一组数据库备份，多组时拒绝并提示。
- [ ] 组装后的 ZIP 可以完成 MSSQL `.bak` 和 MySQL `.sql` 恢复。
- [ ] 数据库任务和恢复测试不依赖真实数据库实例。

## Agent Brief

**Category:** enhancement  
**Summary:** 让 MSSQL 和 MySQL 备份复用分卷、上传和目录恢复能力，并正确报告数据库导出统计。

**Current behavior:**

MSSQL 和 MySQL 任务各自把数据库导出结果打成单个 ZIP，并使用与文件备份相同的整包上传入口。两个任务 DTO 都没有独立分卷上限。数据库恢复只接受一个 `.zip`、`.bak` 或 `.sql` 文件，并从单 ZIP 中提取第一个数据库文件，不能处理下载到同一目录的多个分卷。

两个数据库流程的结构基本一致，但当前没有共享的分卷配置、备份单元记录、目录扫描或组装入口。代码中不存在数据库分卷实现，也没有相关拒绝记录。

**Desired behavior:**

MSSQL 和 MySQL 任务支持与文件任务相同的分卷上限规则：任务值 0 继承全局，正数覆盖全局。每个成功导出的数据库 ZIP 独立执行现有完整 ZIP 流程；超过上限时形成独立分卷和清单，未超限时继续使用单 ZIP。

每个数据库备份包的清单和待传记录包含数据库任务统计：发现或计划数据库数、成功导出数、跳过数和导出文件字节数。分卷上传、逐文件补传、远端校验和任务成功判定继续复用文件备份形成的通用接口，不复制一套数据库专用上传协议。

数据库恢复页允许选择单 ZIP、单 `.bak/.sql`，或包含一组手工下载分卷的目录。目录模式先调用通用分卷扫描和组装器，得到临时完整 ZIP，再把 `.bak` 或 `.sql` 交给现有数据库恢复逻辑。

一个分卷目录只允许一组备份标识。存在多组、缺卷、损坏、重复序号、清单不一致或清单版本不支持时必须拒绝恢复并给出可读错误。组装产生的临时 ZIP 和提取文件在成功或失败后都清理。

**Key interfaces:**

- `MssqlTaskDto` 和 `MysqlTaskDto`：增加分卷上限字段，0 表示继承全局值。
- 数据库任务存储：保存并迁移任务级分卷上限。
- `MssqlRunner` 和 `MysqlRunner`：每个成功导出的数据库包使用通用分卷解析与生成接口，并按现有库名键保存待传项。
- `BackupRunStats`：数据库任务使用计划数据库数、成功导出数、跳过数和导出字节数。
- `PackageSplitter.ScanUnit()` 和 `Assemble()`：处理数据库分卷目录，复用文件恢复的清单校验与组装行为。
- `MssqlRestore` 和 `MysqlRestore`：保留单文件和单 ZIP 入口，同时接受组装器输出的完整 ZIP。
- 恢复页 MSSQL/MySQL 输入：允许选文件或目录；目录模式在后台完成组装后再进入现有数据库恢复流程。
- 邮件运行统计：数据库任务把“发现/打包/跳过”渲染为“数据库/导出/跳过”。

**Acceptance criteria:**

- [ ] MSSQL 和 MySQL 任务都支持 `0=继承全局` 和正数覆盖分卷上限，保存后可正确读取。
- [ ] 未超限的数据库包继续生成并上传单 ZIP。
- [ ] 超限的每个数据库包生成独立分卷单元，不把不同数据库合并到同一分卷单元。
- [ ] 数据库分卷复用文件备份的清单、逐文件上传、远端校验和补传行为。
- [ ] 一个数据库导出失败而其他数据库成功时，成功项继续打包和上传，整次任务仍因跳过数大于零判定失败。
- [ ] 数据库任务邮件显示计划数据库数、成功导出数、跳过数和源大小。
- [ ] MSSQL 恢复支持单 `.bak`、单 ZIP 和包含一组分卷的目录。
- [ ] MySQL 恢复支持单 `.sql`、单 ZIP 和包含一组分卷的目录。
- [ ] 分卷目录包含多组备份时拒绝恢复并说明检测到多组。
- [ ] 分卷目录缺卷、损坏、重复序号或清单版本不支持时拒绝恢复。
- [ ] 目录模式组装成功后能够恢复正常数据库，组装失败时不会调用数据库恢复命令。
- [ ] 临时组装 ZIP、临时提取文件和临时工作目录在成功和失败后都清理。
- [ ] 自动化测试使用假组装结果和可替换数据库命令，不依赖真实 MSSQL 或 MySQL 实例。
- [ ] 至少使用一个真实测试数据库完成手工验收，确认分卷备份、目录组装和恢复链路。

**Out of scope:**

- 重新设计分卷生成、逐文件上传校验或文件恢复；这些由前置工单提供。
- 一个目录中包含多组数据库备份时的自动选择界面。
- 跨数据库批量恢复、并发恢复或恢复进度 UI。
- 修改现有 MSSQL/MySQL 的连接、备份命令、覆盖或权限规则。
- Oracle、达梦和 PostgreSQL 恢复。
- 真实云账号上传与下载验收。
- 恢复当前工作树中无关的已删除测试或部署文件。
