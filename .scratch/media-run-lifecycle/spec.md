## Problem Statement

离线介质任务把窗口判断、等待、介质登记、打包、复制、版本清理、卷离线和整盘离线全部写在一个静态 runner 中。高风险顺序只能靠真实移动盘验证，复制失败、疑似篡改、隔离回退和等待超时难以稳定回归。

## Solution

把离线介质运行拆成三个内部 module：介质包传输、介质隔离和计划等待。公开入口仍保留现有 `ExecuteDue` / `ExecuteNow`，调用者行为不变；磁盘与文件系统通过窄 adapter 注入，测试不依赖真实移动盘。

## User Stories

1. 作为离线介质用户，我希望任务只安排在配置窗口内执行，以便移动盘不会全天暴露。
2. 作为介质未接入的用户，我希望按等待分钟继续检查，并在窗口结束或超时时跳过，以便状态可预测。
3. 作为维护者，我希望登记、序列号、外接盘和备份目录保护在任何写入前检查，以便绝不误写系统盘或产品目录。
4. 作为用户，我希望打包完成后先复制成临时文件再原子替换，以便中断不会留下看似完整的损坏包。
5. 作为用户，我希望离线盘已有同大小且匹配的文件时跳过复制，以便重复执行不重复写盘。
6. 作为用户，我希望复制后大小不一致时任务失败且保留本地 ZIP，以便仍有恢复证据。
7. 作为用户，我希望疑似篡改时暂停旧版本清理，以便不销毁取证线索。
8. 作为用户，我希望成功复制后才删除本地 ZIP，以便失败时不丢失唯一副本。
9. 作为用户，我希望版本清理按最近 M 次和 D 天同时约束，以便保留规则不漂移。
10. 作为用户，我希望完成后立即离线失败时至少去掉盘符，以便盘仍不会继续暴露。
11. 作为使用卷离线的用户，我希望整盘离线不受支持时回退到卷离线，以便 U 盘不会导致任务失败或格式化。
12. 作为维护者，我希望以上顺序可通过文件系统和磁盘 fake 验证，以便不依赖真实移动盘即可回归。

## Implementation Decisions

- 公开入口保持 `MediaRunner.ExecuteDue` 和 `ExecuteNow`，WPF 页面不改。
- 介质包 module 负责打包、去重判断、临时文件复制、大小复核、本地 ZIP 删除、版本清单写入和版本清理。
- 介质隔离 module 负责刷新、隔离、隔离失败后的摘盘符回退和最终盘符复核。
- 计划 module 负责下一次窗口开始、等待开始、等待超时和窗口结束判断。
- SQLite 任务/介质状态仍由现有 store 保存，不迁移表结构或历史字段。
- 磁盘枚举、挂载、卷离线、整盘离线和文件系统作为内部 adapter；测试通过 fake 驱动。
- 保持卷离线默认级别、整盘离线失败回退、疑似篡改暂停清理、失败后到点仍尝试离线等现有规则。

## Testing Decisions

- 从介质包 module 的外部结果测试：成功、跳过、大小不符、篡改和版本清理顺序。
- 从隔离 module 的外部结果测试：已离线、整盘成功、整盘失败回退卷离线、回退仍失败。
- 从计划 module 测试：窗口下一次开始、未到点、等待开始、继续等待、窗口结束跳过和等待超时。
- 不调用真实 `diskpart`、WMI 写入、卷离线或移动盘格式化。

## Out of Scope

- 修改介质登记标识、产品目录名、保留版本格式或 ZIP 格式。
- 新增物理拔出、格式化、分区或自动修复。
- 在测试环境中操作真实移动盘。

## Further Notes

现有产品明确只承诺卷/整盘离线和摘盘符，不承诺物理断开。任何失败路径都不得格式化。
