# 用心云·循备 操作手册

本文按当前程序的按钮和实际动作编写。左下角「官网」用浏览器打开 https://backup.yongxincloud.cn 。登录默认连这个地址。若要改（例如本机调试），在程序旁的 `data\site.url` 写一行网站地址，末尾不要斜杠。拷贝到 Windows Server 2012 / 2012 R2 时必须带上同目录的 `YxyXb.Client.exe.config`，并已安装 .NET Framework 4.8。电脑没有网络时，已保存的离线介质任务到点仍会执行。试用订单、续费顺延、佣金和开票见《用心云·循备-后台系统开发需求文档》。

## 1. 先让引擎跑起来

左侧点 **首页**。未登录时显示「未登录。请先登录或申请帐号」，点 **申请帐号** 打开官网注册页。

1. 看「引擎」。未安装时点 **安装服务**，再点 **启动服务**。
2. 显示运行中之后，到点的任务才会执行。客户端关掉不影响服务。
3. 安装或启动失败时，用管理员身份重新打开客户端再试。
4. **停止服务**、**卸载服务** 只在本软件里做。任务管理器里的“结束任务”停不掉这项服务。若在“详细信息”里结束 `YxyXb.Engine.exe`，大约 1 秒后服务会自己再启动。填了打开密码时，要先输入密码进入软件，再点首页的停止或卸载。
5. **服务内部名** 为 `YxyXbService`（显示名「用心云·循备 Service」）。

主窗口没有系统标题栏。左下角「登录」旁是 **退出**。点开后可选 **最小化**、**退出程序**、**取消**。选最小化后，任务栏不留按钮，右下角通知区域出现图标，双击可打开。

关闭窗口时，若在 **设置 → 综合设置** 勾了关闭到托盘，程序缩到右下角。托盘图标双击或点「打开」可回到窗口，点「退出」才真正退出。

## 2. 日常要用的顺序

做离线介质备份时，按这个顺序：

1. 在 **设置 → 备份存储** 确认备份目录和压缩密码，点保存。zip 会先写到这里，拷到盘上后再删掉这一份。
2. 插入 U 盘或移动硬盘，在 **离线介质 → 登记介质** 登记这块盘。
3. 在 **离线介质 → 介质任务** 添加任务。**打包文件夹** 选要备份的目录（不要选备份目录本身），再填任务开始时间、介质离线时间和隔离级别。
4. 到任务开始时间后，服务把该文件夹里的全部文件打成一个 zip，写入备份目录，再拷到离线盘。大小一致后删除本地这份 zip。成功且勾了完成后立即离线，马上离线。失败也会在介质离线时间到点后离线；若失败时已经过了这个时间，立刻离线。
5. 到 **日志 → 离线介质** 看结果。成功时应有「已打包」和「已删除本地压缩包」。

## 3. 设置

左侧点 **设置**。改完必须点该页的保存。

### 备份存储

- **备份目录**：文件备份和库备份的 zip 放在这里。离线介质打出的 zip 也先写到这里，拷到盘上后再删除这一份。默认是 `D:\yxyxb\bak`。
- **压缩等级**：0 到 9，默认 5。0 几乎不压缩，9 更小更慢。
- **压缩密码**：可空。留空则 zip 不加密。填写后，**之后新打出来的** zip 会要密码才能解压。密码不会写进日志。
- 打开 zip 仍能看到里面的文件名。双击里面的文件或解压时，系统才会要密码。
- 已经生成的旧 zip 不会补上密码。改密码后要再执行一次备份。

### 备份命名

勾选要出现在目录名和文件名里的部分。目录和文件名都可以勾选 **客户标识**。保存后看预览。只影响之后执行的任务。

### 网络传输、FTP、EMAIL

把备份再送到共享目录、FTP 或邮箱时才填。EMAIL 可改邮件标题、邮件内容和邮件结尾。可用 `{任务}`、`{结果}`、`{时间}`、`{详情}`、`{客户标识}`。客户标识取自「综合设置」。标题留空时默认 `{客户标识} {结果} - {任务}`。已经保存过的旧标题不会自动改。主机、发件人、收件人都填了后，出现总开关「任务执行后发送邮件」和下拉「失败 / 成功 / 所有」。总开关默认关。任务对话框仍要勾「完成后发邮件」。填完点保存，再用该页的测试。

### 自动删除

按保留天数删过期 zip。勾选要清理的位置，填天数和每天清理时间，然后保存。勾了七牛或百度时，每个对象删除成功都会在 **日志 → 自动删除** 记「删除调用成功：对象名」。

### 综合设置

- **界面主题**：明亮（默认）、深色、Windows 11、Mac、用心云。保存后立即切换。用心云的侧栏为墨色 `#1C1214`，按钮为正红 `#DC0606`。
- **客户标识**：出现在勾选了该项的备份目录名和文件名里。留空保存后为「用心云循备」。
- **开机启动**、**关闭到托盘**。
- **本机锁定密码**：留空则不锁。保存后，下次启动或从托盘打开时要输入。当前已经打开的窗口不受影响。

## 4. 文件备份和库备份

左侧点 **任务**。

### 文件

点 **添加**。名称、源（本地 / UNC / FTP）、文件夹、周期、下次执行用日期和时间选择后保存。点选该行可 **立即执行**（后台跑，完成后弹结果）。勾了百度云时会弹出上传分片日志窗。也可看 **日志 → 文件备份**。到点后服务也会打 zip。引擎自动执行同样遵守云备份页的上行 / 下行限速。客户端与引擎不会同时打同一任务（运行锁）。

### MSSQL

1. 先到左侧 **实例**，添加 SQL Server 实例并测试连接。
2. 回到 **任务 → MSSQL**，点 **添加**。
3. 可点 **立即执行**。结果看弹窗；勾了百度云时看上传日志窗。也看 **日志 → MSSQL**。多库时每个库一个 zip，文件名带库名。
4. zip 在备份目录的「库备份」下。离线介质不会自动把这些库备份 zip 拷走；介质任务只打包自己指定的文件夹。
5. 服务以 **Local System** 跑时，必须能访问要备份的库。若报「NT AUTHORITY\SYSTEM 无法访问数据库」，给该登录名授权，或改用 SQL 账号。

### MySQL

1. 先到左侧 **实例 → MySQL**，填写服务器、端口（默认 3306）、用户名、密码，点 **测试连接**。
2. 回到 **任务 → MySQL**，点 **添加**。范围可选全部用户库，或填写指定库名（逗号分隔）。
3. 可点 **立即执行**。结果看弹窗，也看 **日志 → MySQL**。多库时每个库一个 zip。

## 4.1 数据库恢复

左侧点 **恢复**（需有效授权）。

### MSSQL

1. 先在 **实例** 配好目标 SQL Server 并测试连接。
2. 选目标实例，浏览备份产生的 `.zip`（内含 `.bak`）或直接选 `.bak`。若 zip 有压缩密码，填上（默认可带出设置里的密码）。
3. 填 **目标库名**。勾选覆盖时会先踢掉已有同名库的连接再 `RESTORE … WITH REPLACE`。
4. 点 **开始恢复**。临时 `.bak` 放在本机公共目录，供 SQL Server 服务读取。

### MySQL

1. 先在 **实例 → MySQL** 配好目标并测试连接。本机需有 `mysql.exe`（或放在程序目录）。
2. 选 `.zip`（内含 `.sql`）或 `.sql`，填目标库名；勾选覆盖会先删再建库。
3. 点 **开始恢复**。

## 4.2 我的设备

左侧点 **我的设备**。列表显示占用中的电脑（名称一般为「电脑名 · MAC · Windows 用户」）、版本与设备上限。可踢出其它设备；踢出本机后立即变为未登录并回到首页。退出登录不释放名额。
4. 备份调用 `mysqldump.exe`。本机已安装 MySQL 客户端时一般能找到；找不到时，把 `mysqldump.exe` 放到程序同一目录。
5. zip 在备份目录的「库备份」下。

Oracle、达梦、PostgreSQL 本期不能用。

## 5. 登记离线介质

左侧点 **离线介质 → 登记介质**。只接受 USB、1394、SD（含 USB 移动硬盘）。系统盘不能登记。

1. 插入磁盘，点 **刷新接入盘**。
2. 在上方列表选中该盘，点 **登记选中**。身份是「序列号 / 签名 / 容量」。
3. 下方「已登记」里点选这一行，再用 **在线/离线**。

**在线/离线** 的动作：

| 当前状态 | 点击后 |
| --- | --- |
| 有盘符且能打开 | 卷离线，并去掉盘符。提示「已卷离线」。资源管理器里不再显示。 |
| 没有能打开的盘符 | 按登记时的卷先上线，再挂盘符。目录能打开才算成功。 |

手点会弹出「离线介质」提示框。程序不会再自动打开资源管理器。

卷离线之后，卷的名字仍可能出现在系统列表里，但读写会被拒绝，直到再次在线。这不是把磁盘从电脑上拔掉。会按卷扫描的程序，仍可能看到这个卷名。

**解绑登记** 只取消软件对这块盘的管理，不删除盘里的文件。

**标记疑似篡改** 后，介质任务会暂停清理旧版本。确认盘没有问题后，点 **确认盘完好**。

## 6. 介质任务

左侧点 **离线介质 → 介质任务**。

点 **添加**，常用项：

| 项 | 怎么填 |
| --- | --- |
| 名称 | 自己认识的任务名 |
| 打包文件夹 | 必填。里面的全部文件打成一个 zip。不要选备份目录，也不要选备份目录里面的文件夹 |
| 目标介质 | 选已登记的盘 |
| 盘内目录 | 默认「用心云循备」 |
| 任务开始时间 | 到这个时间后才检查介质。已在线就执行；未在线则先挂载，挂好再执行。例如 22:00 |
| 介质离线时间 | 到这个时间再查一次。介质仍在线就再执行离线。例如 23:00 |
| 等待就位(分) | 任务开始后盘还没插上时，最多再等多久。到介质离线时间仍没有盘，本次跳过 |
| 保留版本 M、保留天数 D | 只清理离线盘上的旧包。最近 M 次，并且不超过 D 天，先到先删。默认都是 7。不删本地备份目录里别的 zip |
| 冲突 | 覆盖，或跳过已有文件 |
| 周期、间隔、下次执行 | 决定什么时候算到点 |
| 完成后立即离线 | 默认勾选。备份成功后立刻离线，不等介质离线时间 |
| 隔离级别 | 默认 **L2 卷离线**。与按钮「在线/离线」同一档，可以再自动挂回 |

隔离级别不要随便改高：

- **L1 去盘符**：只去掉盘符，卷仍可被按卷路径打开。
- **L2 卷离线**：推荐。去掉盘符，并拒绝读写。下次任务开始或点「在线」时，程序会再挂回来。
- **L3 整盘离线**：部分 U 盘不支持，或离线后挂不回来。
- **L4 PnP 弹出**：盘从系统消失，程序不能自己把它插回来。

保存并保持 **启用**。

### 到点以后程序做什么

1. 到任务开始时间，且到了下次执行时间：介质已在线就直接做；未在线则先挂上盘符。没有提示框，也不打开资源管理器。
2. 把打包文件夹里的全部文件打成一个 zip，写入本地备份目录。
3. 只把这一个 zip 拷到盘内目录。盘上文件大小与本地一致后，删除本地这份 zip。U 盘若是 FAT32，修改时间会对不齐，程序只比大小。
4. 勾了「完成后立即离线」且本次成功时，拷贝一结束就按所选级别离线，不等介质离线时间。
5. 没勾「完成后立即离线」时，成功后盘符留到介质离线时间。
6. 无论成功还是失败，到介质离线时间若盘还在线，一定再离线。失败时若已经过了介质离线时间，立刻离线。已经不在线则不再动。
7. 盘没插上时，在「等待就位」时间内继续等。超时或到介质离线时间仍没有盘，本次跳过。
8. 没有能打开的盘符时，本次不往盘里写文件。

点 **立即执行** 会马上打包并拷贝。成功且勾了完成后立即离线时，拷完同样离线。

日志里成功时应能看到「已打包」「已删除本地压缩包」「任务完成，已立即离线。」到介质离线时间若盘还在，会再写「介质仍在线，已再离线」。

## 7. 云备份

左侧 **云备份**。七牛云填空间 / AK / SK 后保存并测试连接。百度网盘点 **扫码授权** 或 **帐号密码**，成功后勾启用。腾讯云、天翼云不能保存。文件 / MSSQL / MySQL 任务勾云备份并选已启用的服务商时，zip 会再上传一份。任务只能选一个云。SQL Server / MySQL 一次选多个库时，每个库各上传自己的 zip。某一个库失败时，其余库继续传。

七牛和百度都按 4MB 分片。百度可断点续传。同一页填 **上行**、**下行**（KB/s）和并行数（1–2，默认 1）。上行限制上传（云 / FTP / 共享），下行限制 FTP 源下载。填 0 表示该方向不限速。客户端手工执行和引擎自动执行用同一套设置。改完要点保存。分片过程看 **日志 → 分片日志**。七牛文件在 `data\qiniu-upload\`，百度文件在 `data\baidu-upload\`。

## 8. 看结果

左侧点 **日志**。

| 页 | 看什么 |
| --- | --- |
| 文件备份 | 文件任务是否打出 zip，是否写了「已用压缩密码」 |
| MSSQL / MySQL | 库备份是否成功；多库是否各有一份 |
| 离线介质 | 是否挂载、是否拷贝、是否「任务完成，已立即离线」 |
| 自动删除 | 过期包是否删掉。七牛/百度每个对象删除成功会写「删除调用成功：对象名」 |
| 分片日志 | 七牛和百度的开始、分片成功或失败、合并。来源列区分两边。下方为 `data\qiniu-upload\` 与 `data\baidu-upload\` 的文件内容 |

点选一行后下方滚动看全文。每页可 **刷新**、**清空日志**（备份包不会删）。说明栏里的「成功 / 失败」为准。失败时先看说明，再看盘是否插上、服务是否在运行。

## 9. 使用时注意

1. 介质任务拷的是备份目录里的 zip，不会把 U 盘上的文件再压一次。
2. 压缩密码只保护新的 zip。手点「在线」不会给盘上已有文件加密码。
3. 卷离线不是杀毒，也不是把盘从系统里移除。
4. 任务开始后会检查介质是否在线，未在线则先挂载再拷贝。备份完成后会立即离线。到介质离线时间若仍在线，会再离线一次。手点「在线/离线」可以随时切换。
5. 若 Windows 弹出「需要格式化」，点取消。隔离不会格式化磁盘。

## 11. 新版本怎么发布

安装包和版本说明都放在云存储里，公开地址是：

- 安装包：`http://download.yongxinyun.com/yxyxb/yxyxb.zip`
- 版本说明：`http://download.yongxinyun.com/yxyxb/version.json`

客户端有网时，启动约 2 分钟后读取版本说明，之后每 24 小时再读一次。没有网络时不检查。有任务正在执行时不更新。不弹确认框。

### 发布前先改程序里的版本号

打开 `src/YxyXb.Core/AppPaths.cs`，把 `ReleaseVersion` 改成新的三段版本号，例如从 `1.0.0` 改为 `1.0.1`。这次打进安装包的程序，左侧会显示 `Ver 1.0.1`。`version.json` 里的 `version` 必须写成同一个字符串。忘记改时，客户更新完成后仍认为自己是旧版本，会反复下载。

### 打包

编译后的程序放在一个目录里再打成 zip。zip 里的 `YxyXb.Client.exe`、`YxyXb.Engine.exe`、`YxyXb.Update.exe` 要在压缩包根上，不要再套一层文件夹。

不要把客户机器上已有的这些内容打进去：

- `oem.json` 和 OEM 图标
- `data\` 里的登录、任务和数据库

安装包要带上这两份，否则新电脑不能登录、也不能扫码：

- 根目录的 `BaiduApp.json`，里面已填好 `AppKey`、`AppSecret`
- `data\site.url`，一行网站地址，例如 `https://backup.yongxincloud.cn`

自动更新时，客户目录里已经有的 `BaiduApp.json` 和 `data\site.url` 不会覆盖。还没有的会补上。

### 计算校验值

对刚打好的 zip 计算 SHA256。这个值只对这一个文件有效。zip 重新打过或重新上传后，要再算一次。

```powershell
Get-FileHash D:\路径\yxyxb.zip -Algorithm SHA256
```

把结果里的 `Hash` 填进 `version.json` 的 `sha256`。必须是 64 位十六进制。大小写都可以。

### 上传

先上传 zip，再覆盖原来的 `version.json`。两个文件都要能公开下载。

```json
{
  "version": "1.0.1",
  "url": "http://download.yongxinyun.com/yxyxb/yxyxb.zip",
  "sha256": "这里粘贴 Hash"
}
```

`version` 使用 `1.0.0` 这种三段版本号，必须比客户电脑里的版本新才会更新。`url` 必须指向刚算过校验值的那个 zip。`sha256` 为空、长度不是 64，或和下载下来的文件不一致时，客户端删掉临时包，不替换文件，备份继续跑。失败原因写在客户电脑的 `data\updates\last-error.txt`。

### 客户电脑上会怎样

校验通过后，程序用 `YxyXb.Update.exe` 停掉引擎，换掉程序文件，再启动引擎和客户端。下面这些不会被覆盖：

- `oem.json`
- `oem.json` 里 `Icon` 写的那个图标文件
- `data\` 里的登录、任务和数据库
- 已经存在的 `BaiduApp.json` 和 `data\site.url`。客户目录里还没有时，会从安装包补上。

### OEM 怎么配

在 `YxyXb.Client.exe` 旁边放 `oem.json`。没有这个文件就显示用心云·循备。示例：

```json
{
  "ProductName": "示例产品",
  "Company": "示例公司",
  "Phone": "400-000-0000",
  "Icon": "oem.ico"
}
```

`ProductName` 用于窗口标题、左侧名称、托盘和登录窗口。`Company` 在名称下面，`Phone` 在公司名称下面。最下面一行是 `Ver 1.0.0`。`Icon` 只写文件名，图标文件也放在 exe 旁边，只换窗口和托盘图标。资源管理器里 exe 自己的图标不变。颜色不在这里配，仍用客户端原来的主题。备份目录、客户标识、百度文件夹名和授权都不读这个文件。
