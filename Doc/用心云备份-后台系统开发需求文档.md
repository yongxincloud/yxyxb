## 1. 项目概述

### 1.1 一句话

**用心云备份** = Windows 桌面备份客户端 + 本机任务引擎 + 配套网站。客户端安装后**必须登录**，由网站鉴权并下发授权周期。没有有效授权时，文件备份、数据库备份、云、UNC、FTP、邮件不可用。**离线介质在无网时仍可执行。** 试用通过订单系统的试用订单发放，每客户最多 2 次，每次 30 天：第 1 次 **0.1 元**，第 2 次 **0.5 元**，均走支付。

### 1.2 系统构成

```text
用心云备份
├── 网站 —— 本次开发主体
│   ├── 前端（Yxy.Web，Vue 3）
│   │   ├── 介绍主页（1 个）+ 购买入口
│   │   ├── 账号：注册、登录、找回密码
│   │   ├── 门户：我的订阅 / 订单 / 续费 / 申请开票 / 申请服务商
│   │   ├── 服务商：我的客户 / 佣金 / 发起结算
│   │   └── 厂商后台：服务商（等级）/ 客户 / 产品 / 订单 / 授权 / 佣金结算 / 开票 / 日志
│   └── 后端（Yxy.Api，ASP.NET Core 8 Web API）
│       └── JSON 接口：网站页面与客户端鉴权、token 签发与续期
└── 桌面端（已有，仅做鉴权对接）
    ├── 用心云备份 客户端（Yxy.Client）
    └── 用心云备份 Service（Yxy.Engine）
```

### 1.3 本期范围

**做：**

1. 介绍主页 + 购买入口
2. 账号体系（注册、登录、找回密码）
3. 订单与支付（微信 / 支付宝）
4. 订单 → 授权有效期联动 + 客户端鉴权（含每客户最多 2 次、每次 30 天的试用订单）
5. 服务商（等级制、客户归属、佣金、结算；退款与销售在同一次结算轧差）
6. 开票（客户可选开或不开；要开由厂商开具。另有服务商佣金发票）
7. 厂商后台

**不做：**

1. 桌面端的备份 / 离线介质 / MSSQL 功能（另有文档）
2. 第三方扫码登录 / 扫码注册 / 账号关联（微信、支付宝、QQ）
3. 多级服务商（只做两级）
4. 企业多席位 / 子账号
5. 纸质发票
6. 介绍主页之外的营销页
7. 佣金自动打款（做到"厂商审批 + 付款 + 回写凭证"）
8. 客户端备份日志上报，以及在网站上查看这些日志。日志只留在客户端本机。厂商后台的 `operation_log` 只记后台操作，不是备份日志

### 1.4 名词定义

| 术语 | 含义 |
| --- | --- |
| **厂商** | 平台方，最高且唯一层级；**唯一收款方** |
| **服务商** | 唯一分销层级，彼此平级；按**等级**拿佣金 |
| **客户** | 最终用户，归属一个服务商或直接归厂商 |
| **等级** | 服务商级别，一个等级对应一个**佣金比例** |
| **授权周期** | 客户端可用的时间区间，由正式订单、试用订单或后台发放决定 |
| **结算** | 服务商发起 → 开佣金发票给厂商 → 厂商审批付款 |

## 2. 商业模式

### 2.1 目标客户与定价

| 项 | 口径 |
| --- | --- |
| 目标客户 | **中小企业内的个人使用者**（一人一账号，公司买单或个人自付） |
| 授权形态 | 一个账号**不限台数、不绑机**，只验账号有效 |
| 当前标准价 | **12 元 / 年**。正式订单周期固定 **365 天** |
| 定价性质 | **随时可改**：现在 12 元/年，后期可能调为 **120 元/年**，系统必须两侧都支持 |

**价格变更规则（必须满足 12 元 → 120 元的跨档调整）**

| 规则 | 口径 |
| --- | --- |
| 改价入口 | 厂商后台 → 产品与定价 → 修改产品价格；也可**新增产品**并存（如"标准版 12 元/年"与"专业版 120 元/年"） |
| 生效范围 | 改价**只影响修改之后新生成的订单**；已生成订单（**含未支付**）按各自的**金额快照**执行 |
| 订单快照 | 下单时把 `amount` 写入订单，之后**永不回读产品现价** |
| **续费价格** | 续费按**续费当时的当前价**下单（12 元买入的客户，续费时可能已是 120 元） |
| 周期天数 | 正式订单**固定 365 天**。产品页只改价格，**不能改天数**。续费在原到期日上加 365 天。发放授权另计，见 §3.4 |
| 佣金联动 | 佣金 = 订单金额 × 等级比例，**自动适配任意价格**（12 元或 120 元） |
| 审计 | 改价写 `operation_log`（操作人、时间、前后价格） |
| 展示 | 介绍主页与购买页的价格**从数据库读取**，**不得写死** |
| 金额精度 | `DECIMAL(10,2)`，12 元与 120 元均无精度问题 |

### 2.2 角色结构

```text
厂商（最高且唯一层级，唯一收款方）
  └── 服务商（唯一分销层级；多家，彼此平级；各自属于一个等级）
        └── 客户
```

| 规则 | 内容 |
| --- | --- |
| 层级 | **只有两级**：厂商 → 服务商 → 客户 |
| 服务商关系 | 彼此**平级**，无上下级、无链路 |
| 客户归属 | 扫**服务商推广码**注册 → 归该服务商；官网直接注册 → 归厂商；厂商后台可手工调整 |
| 归属变更 | 客户与服务商均不可自助修改；仅厂商后台可改，并记审计 |
| 厂商直客 | 客户无归属服务商时，订单**全额归厂商**，**不生成佣金明细** |

### 2.3 资金流

```text
客户（微信 / 支付宝）── 12 元 ──▶ 厂商账户        收入一律进厂商账
客户 ◀──── 发票 ──── 厂商                        客户发票由厂商开
服务商 ── 开票（佣金）──▶ 厂商                    服务商开佣金发票给厂商
厂商 ── 付款 ──▶ 服务商                          厂商收到票后付款
```

| 项 | 口径 |
| --- | --- |
| 收款方 | **厂商**（唯一收款方） |
| 客户发票 | **厂商开**（开票主体与收款方一致） |
| 服务商收入 | **佣金**，以「服务商开票给厂商 + 厂商付款」的方式结算 |
| 结算周期 | **以自然月为单位**（每月结算上一个自然月） |

## 3. 账号与鉴权

### 3.1 账号模型

```text
账号 account（邮箱 + 密码）
  └── 客户档案 customer → 归属服务商，或归厂商
```

| 项 | 口径 |
| --- | --- |
| 账号主体 | **邮箱（登录名）+ 密码** |
| 邮箱 | **必填且唯一**，用于登录、接收验证码、接收电子发票 |
| 手机号 | **选填**，仅作联系方式，不参与登录 |
| 第三方关联 | **不做**（无微信 / 支付宝 / QQ 绑定） |

### 3.2 注册

| 项 | 要求 |
| --- | --- |
| 入口 | **只有网站注册页**。厂商后台不能新建账号 |
| 字段 | 邮箱、密码、确认密码 |
| 校验 | 邮箱格式与唯一性、**邮箱验证码**、密码强度、两次一致、图形验证码、同 IP 限频 |
| 密码存储 | **加盐哈希（PBKDF2 / BCrypt），不存明文、不回显** |
| 归属绑定 | 注册链接可带服务商推广参数（`provider_no`）→ 注册即绑定客户归属 |

### 3.3 登录（两条路）

| 方式 | 网站 | 客户端 | 说明 |
| --- | --- | --- | --- |
| **邮箱 + 密码** | ✔ | ✔ | 主路径 |
| **邮箱 + 邮箱验证码** | ✔ | ✔ | 免密登录 |

| 项 | 要求 |
| --- | --- |
| 验证码 | 6 位数字，**5 分钟有效**，用后作废 |
| 发送渠道 | **邮件（SMTP）**，不用短信 |
| 限频 | 同邮箱 60 秒内只能发 1 条；每日上限（建议 10 条） |
| 失败锁定 | 密码方式连续失败 5 次锁定 15 分钟 |
| 找回密码 | 走邮箱验证码重置 |
| 防枚举 | 登录失败不区分"账号不存在"与"密码错误" |

### 3.4 后台直接启用（厂商后台）

厂商后台可**直接为某账号发起启用**，用于线下成交、赠送、补偿等场景：

| 项 | 要求 |
| --- | --- |
| 账号 | 只能选择**已经在网站注册**的账号。后台不能新建账号 |
| 入口 | 厂商后台 → 客户管理 → **发放授权** |
| 操作 | 选账号 + 选产品 + **手选时长或直接选到期日** → 生成授权 |
| 天数 | 赠送、补偿可手选，**不受**正式订单 365 天限制。不改产品上的 365 天 |
| 记录 | 记操作人、时间、事由、所选时长或到期日；写 `operation_log` |
| 效果 | 授权生效后，客户端可用方式与付费授权相同 |
| 收款 | **线下收款**。不生成销售订单，不进入服务商销售记录，不计佣金 |

### 3.5 客户端鉴权（硬门槛）

| 项 | 口径 |
| --- | --- |
| 是否必须登录 | **必须**。未登录 → 文件备份、数据库备份、云、UNC、FTP、邮件不可用 |
| 鉴权对象 | 网站：账号有效性 + 授权状态 + 授权到期时间 |
| 鉴权失败 | 未登录 / 账号禁用 / 宽限期结束仍未续费 / 暂停 / 取消 → **停用**文件备份、数据库备份、云、UNC、FTP、邮件 |
| 离线介质 | **不访问网站**。电脑无网，或联网校验未成功时，离线介质任务仍按计划执行。宽限期已结束、未登录、暂停、取消时，只要本机无网，离线介质仍执行 |
| 本机保存 | **只存网站签发的 token（密文）**，**不保存网站密码** |
| token | 有效期 = 本次 `next_check_days` + 14 天，必须长于校验间隔和 7 天失败缓冲。校验成功时换发新 token，客户端替换本机保存的旧 token。旧 token 在原到期前仍有效，避免新 token 没保存成功就把客户锁在外面。改密码或后台封禁时**立即吊销**该账号全部 token |
| 台数 | **不限台数、不绑机**；`device_id` 仅用于审计 |

**接口约定**

| 接口 | 用途 | 入参 | 出参 |
| --- | --- | --- | --- |
| `POST /api/client/login` | 邮箱 + 密码登录 | 邮箱、密码、设备标识 | token、账号状态、授权状态、`auth_end_time`、`next_check_days` |
| `POST /api/client/login-code` | 邮箱验证码登录 | 邮箱、验证码、设备标识 | 同上 |
| `POST /api/client/verify` | 校验 token。成功时换发新 token | token、设备标识 | 是否有效、新 token、授权状态、`auth_end_time`、`next_check_days` |
| `POST /api/client/renew` | 续期 | token | 新 token、`auth_end_time`、`next_check_days` |

### 3.6 在线校验频率与宽限期（分段）

客户端**必须在规定间隔内成功联网校验一次**，间隔按**剩余订阅时间**分段：

| 阶段 | 剩余订阅期 | 联网校验间隔 |
| --- | --- | --- |
| 常规期 | **> 1 个月** | **每 30 天 1 次** |
| 收尾期 | **≤ 1 个月** | **每 7 天 1 次** |
| 到期后 | 已过期 | **7 天宽限期** |
| 宽限期结束 | — | **仍未续费 → 停止文件备份、数据库备份、云、UNC、FTP、邮件；无网时离线介质仍执行** |

**规则细节：**

1. 分段以 `auth_end_time − 当前时间` 计算：> 30 天 → 间隔 30 天；≤ 30 天 → 间隔 7 天；
2. 到期后进入 **7 天宽限期**。宽限期内续费 → 在原 `auth_end_time` 上**顺延**，恢复正常；
3. 宽限期结束仍未续费 → **停止**文件备份、数据库备份、云、UNC、FTP、邮件；
4. 校验失败（无网 / 服务不可达）→ **该间隔 + 7 天缓冲**内必须成功校验一次，否则停止第 3 条所列功能；
5. **离线介质**不访问网站。无网或联网校验未成功时，离线介质任务仍执行；
6. 客户端界面显示**"下次需联网校验时间"**与剩余天数；
7. 间隔由**服务端下发 `next_check_days`**，客户端按值执行，**不硬编码阈值**；
8. 间隔到期前 **3 天**开始提示；
9. 校验成功必须换发新 token。新 token 有效期 = 本次 `next_check_days` + 14 天，保证下一次校验日 token 仍未过期。

### 3.7 授权周期与订单

| 项 | 口径 |
| --- | --- |
| 周期来源 | 正式订单 `auth_end_time = pay_time + 365 天`。试用订单为支付时间加 30 天，或在原到期日上加 30 天 |
| 首次授权 | **支付成功后立即生效**，客户端立即可用 |
| 续费 | 在原 `auth_end_time` 上**加 365 天**，**不是从今天重算**。宽限期内续费、宽限期结束后再续费，都从原到期日加算 |
| 授权状态 | 有效 / 过期 / 暂停 / 取消 |
| 记录 | 一订单一条授权记录，取 `auth_end_time` 最大者为当前有效（保留历史） |

## 4. 服务商

### 4.1 申请与审批

| 项 | 口径 |
| --- | --- |
| 门槛 | 注册客户可进入申请页。须为**公司**：公司名称、税号、营业执照、联系人、邮箱、手机号全部必填。缺一项不能提交。个人申请不能通过 |
| 入口 | 门户「申请成为服务商」 |
| 流程 | 客户提交申请 → **厂商审批** → 通过后建服务商号并**指定等级**。材料不是公司的，厂商驳回 |
| 审批材料 | **公司名称、税号、营业执照、联系人、邮箱、手机号** |
| 生效时间 | 审批通过记 `effective_at` |

### 4.2 等级与佣金比例

**佣金比例由「等级」决定。**

| 项 | 口径 |
| --- | --- |
| 等级维护 | **厂商后台可自行增加、修改等级**（数量不限、名称自定） |
| 比例 | 每个等级一个**佣金比例**，可随时修改 |
| 改比例的影响 | **只影响修改之后的新订单**；历史订单按成交时的**比例快照**计算，不重算 |
| 服务商归级 | 签约时指定；可调整 |
| 审计 | 等级增改、比例变更、服务商改级，均写 `operation_log`（含前后值） |

### 4.3 客户归属与推广码

| 项 | 口径 |
| --- | --- |
| 推广码 | 每个服务商一个专属推广链接/二维码，带 `provider_no` |
| 归属时机 | **注册那一刻**自动绑定，不需要事后人工归属 |
| 归属调整 | 仅厂商后台可改（有审计） |

### 4.4 状态与解约

| 状态 | 含义 |
| --- | --- |
| 启用 | 可发展客户、产生佣金 |
| 禁用 | 暂停使用。厂商可把它恢复为启用。禁用期间名下客户的新付款**不计佣金**，金额全额归厂商。客户归属不变。恢复启用之后的新付款再按等级比例计算 |
| 冻结 | 只在解约后出现，不能恢复为启用或禁用 |

状态流转：启用与禁用可以互相切换。启用或禁用都可以解约进入冻结。冻结不能再改回。

**解约规则：** ① 冻结该服务商（停止发展新客户、停止产生新佣金）；② 其名下客户**全部回归厂商**；③ **解约前已产生、尚未结算的销售与退款仍按该服务商结算**。解约之后才支付成功的订单归厂商，不计入原服务商销售记录。

### 4.5 数据可见范围

1. 服务商只看**自己的客户**与**自己的佣金**，看不到厂商所得，也看不到其他服务商；
2. 客户只看自己的订阅、授权、订单、发票；
3. 厂商可见全部。

## 5. 商品、订单与支付

### 5.1 产品

产品可后台维护：编号、名称、描述、**价格**、上下架状态。正式订单周期固定 365 天，不在后台修改。

| 规则 | 口径 |
| --- | --- |
| 改价 | 后台可直接修改价格；**只影响之后新生成的订单** |
| 多产品并存 | 也可**新增产品**承载不同价位（如"标准版 12 元/年"、"专业版 120 元/年"） |
| 订单快照 | 下单时写入 `amount`，之后不随产品改价变化 |
| 未支付订单 | 未支付期间按该单的金额快照。**30 分钟**未支付改为 **已关闭**（`pay_status = 3`）。已关闭不能再支付，晚到的支付回调也不入账、不生成授权。客户要买须重新下单，按当时价格 |
| 下架 | 下架后不可新购；**已购授权不受影响**，到期仍可续费到同产品（若已下架，引导到替代产品） |
| 审计 | 价格变更写 `operation_log`（含前后价格）。周期天数不提供修改 |

### 5.2 订单

订单记录：客户、产品、**金额快照**、**归属服务商**、**佣金比例快照**、支付状态、支付时间、支付渠道、渠道交易号、是否已计算佣金。

字段明细见 §9.2 `subscription_order`。

### 5.3 支付

| 项 | 要求 |
| --- | --- |
| 渠道 | 微信支付（Native 扫码 / JSAPI）、支付宝 |
| **支付成功流程** | 回调 → 更新订单 → **调整账号服务有效期（生成/顺延授权）** → 计算佣金 |
| **回调幂等** | 以 `order_no` + 渠道交易号做唯一约束，**防重复入账** |
| 对账 | 与微信 / 支付宝账单日对账，差异告警 |
| 手续费 | 约 0.38%~0.6%；**佣金基数为订单面额**（当前 12 元，改价后随之变化），手续费由厂商承担 |
| 购买入口 | 介绍主页「立即购买」→ 已登录则进订单系统；未登录先去注册或登录。匿名不能提交正式订单、续费或试用订单 |

### 5.4 退款

| 项 | 口径 |
| --- | --- |
| 退款窗口 | **支付后 7 天内**可退款 |
| 销售记录 | 佣金只按该服务商的**销售记录**结算。退款成功后为该服务商写一条**负数**记录 |
| 结算轧差 | 同一次结算把未结算的正数与负数放进**同一张结算单**相抵后付款。已付款的结算单不改写 |
| **账号与时效** | 退款成功后撤销或缩短对应授权，客户端下次校验即失效 |
| 超窗口 | 超过 7 天不退款，不写负数销售记录 |

### 5.5 续费

- 续费 = 新订单 + 授权在原 `auth_end_time` 上**加 365 天** + 按**续费时的等级比例**重新计算佣金；
- 顺延基准永远是原到期日，宽限期内或宽限期结束后再续费都一样，**不是从付款当天重算**；
- **续费按续费当时的当前价**：早期 12 元买入的客户，若价格已调到 120 元，则按 **120 元**续费；
- 门户续费页须**明确显示当前续费价格**，避免预期落差；
- 门户提供明显的续费入口（续费率是关键指标）。

### 5.6 试用订单

客户在订单系统购买试用，用来获得 30 天授权。必须走微信或支付宝，支付成功后授权才生效。

| 项 | 口径 |
| --- | --- |
| 次数 | 每个客户**最多 2 次**。只计**支付成功**的试用订单。未支付关闭的不占次数。第 3 次拒绝 |
| 第 1 次 | **0.10 元**，30 天 |
| 第 2 次 | **0.50 元**，30 天 |
| 周期 | 固定 **30 天**。正式订单固定 365 天。这两处天数不能在产品里改。发放授权仍可手选时长或到期日 |
| 支付 | 与正式订单相同：微信 / 支付宝，回调幂等。未支付 **30 分钟**改为已关闭，不能再支付，不占试用次数 |
| 价格存放 | 两次价格写入配置，页面从库读取，不写死。改价只影响之后新生成的试用订单，已生成订单按金额快照 |
| 生效 | **支付成功后**生成授权 |
| 起算 | 当前没有未过期的到期日：`auth_end_time = pay_time + 30 天` |
| 顺延 | 已有 `auth_end_time`（含仍在 7 天宽限期内）：在原到期日上**加 30 天**，不从支付当天重算 |
| 佣金 | **不计佣金**，不进入服务商销售记录。退款只退客户款项并缩短授权，不写佣金负数 |
| 记录 | `subscription_order.order_type = 2`，`amount` 为 0.10 或 0.50 |

## 6. 佣金与结算

### 6.1 佣金计算

```text
服务商佣金 = 订单金额 × 该服务商所属等级的 commission_rate   （四舍五入到分）
厂商所得   = 订单金额 − 服务商佣金
```

| 项 | 口径 |
| --- | --- |
| 触发时机 | 正式订单支付成功后写正数；7 天内退款成功后写负数。试用订单与后台发放不写。支付当时服务商为禁用或冻结的，不写佣金，金额全额归厂商 |
| 自购 | 付款账号就是某个**启用中**服务商本人时，这笔正式订单的 `provider_id` 记该服务商自己，按**该服务商当前等级比例**计佣金。不因自购改归厂商。试用、禁用、冻结仍不计佣金 |
| 幂等 | 同一订单、同一服务商：销售一条、退款一条。唯一约束为 `(order_id, provider_id, entry_type)` |
| 金额守恒 | 服务商佣金 + 厂商所得 = 订单金额（差额法，吸收舍入误差） |
| 精度 | 四舍五入到分；人民币；`DECIMAL(10,2)` |
| 快照 | 订单存 `provider_id`、`commission_rate_snapshot`、`pay_time` |

**金额示例（比例为示例，价格 12 元与 120 元两档）**

| 订单金额 | 等级比例 | 服务商佣金 | 厂商所得 | 合计 |
| --- | --- | --- | --- | --- |
| 12 元 | 70% | 8.40 | 3.60 | 12.00 |
| 12 元 | 60% | 7.20 | 4.80 | 12.00 |
| 12 元 | 50% | 6.00 | 6.00 | 12.00 |
| **120 元** | 70% | 84.00 | 36.00 | 120.00 |
| **120 元** | 60% | 72.00 | 48.00 | 120.00 |
| **120 元** | 50% | 60.00 | 60.00 | 120.00 |
| 任意 | — | 0 | 全额 | 客户归厂商时不生成佣金明细 |

> 公式与价格无关：**换任意价格，佣金与厂商所得自动按比例重算，两者之和恒等于订单金额**。

### 6.2 佣金明细

佣金**只按服务商的销售记录**结算。每笔已支付的正式订单写一条正数（`entry_type = 1`）。7 天内退款成功再写一条负数（`entry_type = 2`）。结算时把该服务商尚未结算的正数和负数放进同一张结算单，相抵后付款。已付款的结算单不改写。服务商只看自己的明细，厂商后台看全部。试用订单、后台发放，以及支付当时服务商处于禁用或冻结的订单，不进入销售记录，金额全额归厂商。启用中的服务商自己购买正式订单，按自己的等级比例计入自己的销售记录。

### 6.3 结算（单向）

**收入全进厂商；服务商发起结算 → 开票给厂商 → 厂商付款。**

| 项 | 口径 |
| --- | --- |
| 结算方向 | **只有单向：厂商 → 服务商**（佣金） |
| 周期 | **以自然月为单位**：每月结算**上一个自然月** |
| 发起方 | **服务商发起**（不是厂商主动推款） |
| 触发路径 | 服务商后台「我的佣金 → 发起结算」→ 上传**佣金发票** → 厂商审批 → 付款 → 回写流水号 |
| 数据来源 | 该服务商**未结算的销售记录**（正数与退款负数一起列入本次结算单，相抵后付款）。提交后这些记录冻结，不再进入其他结算单 |
| 最低起结 | 按本次拟结算记录的**净额**计，**满 100 元**才起结。净额不足 100 元或净额为负时不起结，记录留在未结算池，下次与新的销售一起轧差 |
| 状态 | 待提交 / 待审批 / 已批准 / 已付款 / 已驳回 |
| 驳回 | 厂商驳回须填原因；明细解锁回可结算池 |
| 凭证 | 服务商上传**佣金发票**与收款信息；厂商回写付款流水号 |
| 冲正 | 已结算后又发生窗口内退款 → 负数留在未结算池，**下一张结算单与其他未结算销售一起轧差**；已付款结算单不改 |
| 挂账提醒 | 长期未发起结算（如超 12 个月）自动提醒并触发人工清理 |

> **为什么必须按月合并结算：** 单笔佣金 = 订单金额 × 等级比例。12 元价下为 6.00~8.40 元，逐单转账（每笔通常 1~5 元）**手续费可达佣金额的 10%~40%，甚至倒挂**；120 元价下为 60.00~84.00 元，逐单虽不再倒挂但成本仍高。**两种价位都按"自然月合并 + 最低起结"执行，规则不随价格变化。**

### 6.4 开票

| 对象 | 开票方 | 说明 |
| --- | --- | --- |
| **客户** | **厂商** | 客户选择「开票」或「不开票」。选择开票后由**厂商**开具并发送 |
| **服务商** | **服务商** | 服务商给**厂商**开**佣金发票**，作为结算的前置条件 |

**客户开票**

| 项 | 口径 |
| --- | --- |
| 是否开票 | 客户自行选择**开票**或**不开票**。选不开票不创建开票申请 |
| 客户提供 | **公司抬头**、**税号**、**邮箱**、**营业执照（JPG 或 PNG）** |
| 发起方 | 客户在门户提交申请 → **厂商待办**，由厂商统一开具 |
| 交付 | **电子发票**发到邮箱 + 门户可下载 |
| 介质 | 电子发票（PDF / OFD）；纸质不做。营业执照只收 JPG、PNG |
| 合并规则 | **允许多单合并开票**（12 元单价下必需） |
| 状态机 | 待提交 → 待受理 → 开票中 → 已开票 → 已发送 / 已作废 |

**服务商佣金发票**

| 项 | 口径 |
| --- | --- |
| 开票方 / 受票方 | **服务商 → 厂商** |
| 金额 | 本次结算单的佣金总额 |
| 用途 | 结算的**前置条件**：未上传发票，厂商不审批付款 |

```sql
-- ==================== 账号与鉴权 ====================

CREATE TABLE account (
  id            BIGINT       NOT NULL AUTO_INCREMENT,
  email         VARCHAR(128) NOT NULL COMMENT '邮箱（登录名）',
  password_hash VARCHAR(200) NOT NULL COMMENT '加盐哈希，禁止明文',

  updated_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_account_email (email)
```

### 9.3 关键约束与不变式

1. **服务商佣金 + 厂商所得 = 订单金额**（可写成定时对账任务）；
2. 每笔已支付正式订单、每个服务商最多一条销售佣金和一条退款佣金（`UNIQUE(order_id, provider_id, entry_type)`）；试用订单与后台发放不产生佣金；
3. 客户只有一个 `direct_provider_id`；服务商**无上级**；服务商**必须属于一个等级**；
4. 等级 `commission_rate` 在 `(0, 1)`；改等级比例**不重算**历史订单；
5. 订单的 `commission_rate_snapshot` 成交后**不可修改**；
6. 已付款结算单不可修改。退款只新增负数销售记录，与未结算正数在同一次结算中轧差；
7. 邮箱唯一；`auth_token` 只存哈希；
8. 结算单**必须附佣金发票**才能进入审批；
9. 授权 `auth_end_time` 只由 **正式订单支付**、**试用订单支付** 或 **厂商后台发放** 驱动，不手工改库；续费与再次试用都在原到期日上顺延；
10. 退款成功必须**同时**回写订单、授权，并写入该服务商的负数销售记录；结算时与未结算正数一起轧差；
11. **改价不改历史**：只改价格，正式订单天数固定 365。价格变更只影响**之后新生成**的订单；已生成订单按其 `amount` 快照执行，**已生效授权与到期时间不受影响**；
12. 佣金公式与价格无关：**换任意价格，佣金与厂商所得自动按比例重算，两者之和恒等于订单金额**。

### 9.4 主要状态机

| 对象 | 状态流转 |
| --- | --- |
| 订单 | 未支付 → 已支付 → 已退款；未支付 → 已关闭（超时，不可再支付） |
| 授权 | 有效 → 过期 / 暂停 / 取消 |
| 服务商申请 | 待审批 → 已通过 / 已驳回 |
| 结算单 | 待提交 → 待审批 → 已批准 → 已付款 / 已驳回 |
| 客户开票 | 待提交 → 待受理 → 开票中 → 已开票 → 已发送 / 已作废 |
| 服务商 | 启用 ↔ 禁用；启用或禁用 → 冻结（解约，不可恢复） |

## 10. 技术选型

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 网站前端 | **Vue 3** | 介绍主页、账号、客户门户、服务商门户、厂商后台全部用 Vue 3。Vite 构建，Vue Router 管路由。不使用 Razor / MVC 视图，也不把 Vue 以无构建方式嵌进服务端页面 |
| 网站后端 | **ASP.NET Core 8 Web API** | 只提供 JSON，给 Vue 页面和桌面客户端共用。桌面端仍是 .NET Framework 4.8，两套运行时分开 |
| 介绍主页收录 | **构建时预渲染 `/`** | 唯一对外营销页。预渲染 HTML 带标题与产品说明。价格仍从接口读取，页面不写死 |
| ORM | EF Core 8 | 迁移生成 SQLite / libSQL 表，开发库与 Turso 用同一套结构 |
| 数据库 | 开发联调：**本地 SQLite**。上线：**Turso** | 访问用 Turso 的数据库 URL 和令牌。令牌放配置，不写入仓库。不使用 MySQL |
| 定时任务 | Quartz.NET 或 `BackgroundService` | 授权到期扫描、退款冲正窗口判定、月度结算提醒、对账 |
| 支付 | 微信支付 + 支付宝 | 回调必须**验签 + 幂等** |
| 邮件 | **SMTP** | 邮箱验证码、开票通知、结算通知、授权到期提醒 |
| 部署 | Linux + Nginx 或 Windows + IIS | **必须 HTTPS + 域名备案**（支付前置条件） |

## 12. 验收要点

**账号与鉴权**

1. 网站可用**邮箱 + 密码**注册；邮箱唯一；密码加盐哈希存储。
2. 网站可用**邮箱 + 邮箱验证码**登录；验证码 5 分钟有效、同邮箱限频。
3. **不存在任何扫码登录入口**（微信 / 支付宝 / QQ 均无）。
4. 找回密码走邮箱验证码，可正常重置。
5. 厂商后台可**直接为已注册账号发放授权**（选产品 + 手选时长或到期日），客户端立即可用。后台不能新建账号。这次手选不改变正式订单的 365 天。
6. **客户端未登录时**，文件备份、数据库备份、云、UNC、FTP、邮件不可用；**无网时离线介质仍可执行**。登录后在授权有效期内可用；**只保存 token、不保存网站密码**；token 可被吊销。token 有效期 = `next_check_days` + 14 天。校验成功换发新 token，旧 token 在原到期前仍有效。
7. 同一账号在两台机器同时登录均可用（**不限台数**）。

**授权与订单**

8. **订单支付 → 授权自动生效**：正式订单 `auth_end_time = pay_time + 365 天`。后台不能把正式订单天数改成别的值。
9. 续费在原 `auth_end_time` 上**加 365 天**，不是从今天重算。宽限期结束后再续费，同样从原到期日加 365 天。
10. 未登录、账号禁用、授权暂停、授权取消，以及**宽限期结束仍未续费**：文件备份、数据库备份、云、UNC、FTP、邮件停用。无网时离线介质仍可执行。
11. 12 元订单：微信、支付宝各完成一次真实支付；**重复回调不重复入账**。
12. **分段在线校验**：剩余 > 1 个月 → 每 30 天必须成功联网 1 次；≤ 1 个月 → 每 7 天 1 次；到期后 7 天宽限期；宽限期结束仍未续费 → 停用第 10 条所列功能。间隔由服务端 `next_check_days` 下发。校验成功换发的 token 在下一次校验日仍有效。无网或联网校验失败**不停止离线介质**。
13. **后台发放授权**不产生销售订单，不计佣金。
14. **试用订单**：每客户最多支付成功 2 次。第 1 次 **0.10 元**、第 2 次 **0.50 元**，均走微信或支付宝，支付成功后生效，周期各 30 天。未支付关闭不占次数。已有到期日时在原 `auth_end_time` 上加 30 天。第 3 次被拒绝。**不计佣金**，不进入服务商销售记录。

**服务商与佣金**

15. 注册客户申请服务商时，公司名称、税号、营业执照、联系人、邮箱、手机号缺一不可。个人申请不能通过。厂商审批通过后**指定等级**并生效。
16. **等级可增改**：厂商后台新增 / 修改等级与佣金比例；改后**历史订单佣金不变**，新订单按新比例。
17. 按 §6.1 造单核对：服务商佣金 + 厂商所得 = 12.00；客户归厂商时**不产生佣金明细**。启用中的服务商自己购买正式订单，佣金按该服务商自己的等级比例计入其销售记录。
18. 同一订单重复触发佣金计算，销售记录不增加。同一订单的退款只增加一条负数。
19. 权限：服务商 A 看不到服务商 B 的客户与佣金，也看不到厂商所得。
20. 禁用可恢复为启用。禁用期间名下客户的新付款不计佣金，金额全额归厂商，客户归属不变；恢复启用后的新付款再计佣金。解约后变为冻结，不能恢复。解约时其名下客户**全部回归厂商**，**解约前未结算的销售与退款照常结算**。解约后才支付的订单不计入原服务商。

**结算与开票**

21. 服务商按**自然月**发起结算 → **上传佣金发票** → 厂商审批 → 付款。同一张结算单内正数销售与退款负数相抵；净额未达 100 元不起结。
22. **未上传佣金发票不能进入审批**。
23. **退款成功 → 账号与使用时效同步更新**：授权被撤销或缩短，客户端下次校验即失效。7 天内的退款写入负数销售记录，与未结算正数在同一次结算轧差。已付款结算单不改。
24. 客户可选择**不开票**。选择开票时提交公司抬头、税号、邮箱、JPG 或 PNG 营业执照 → **厂商**开票 → 客户**邮箱收到 + 门户可下载**；支持**多单合并开票**。

**界面与合规**

25. **介绍主页只有 1 个**。「立即购买」在未登录时进入注册或登录，登录后才能下单、续费、买试用。匿名提交订单被拒绝。
26. 门户在 375 / 768 / 1440 / 1920 四档断点无横向滚动。
27. 购买页、支付成功页、用户协议明示：客户可选开票或不开票，要开票由**厂商**开具，并明示「一个账号不限台数」。

**价格与定价**

28. **改价只影响新订单**：后台把价格从 **12 元改为 120 元**后 —— 已生成的订单（**含未支付**）金额**不变**；新订单为 **120 元**；已生效授权与到期时间**不受影响**。
29. **改价联动佣金**：120 元订单按等级比例正常计算（60% → 服务商 **72.00**、厂商 **48.00**），**佣金 + 厂商所得 = 订单金额**。
30. **改价联动展示**：介绍主页与购买页的价格随后台改动**自动变化**，页面**不写死**价格。
31. **续费按当前价**：12 元买入的客户在价格调到 120 元后，续费页显示 **120 元**，并按 120 元下单，在原到期日上顺延。
32. **未支付订单超时关闭**：下单后 30 分钟未支付，`pay_status` 变为已关闭。该单不能再支付，晚到回调不入账、不生成授权。客户重新下单时按当时价格。

| --- | --- |
| 厂商 | 平台方，唯一收款方，规则制定与审批者 |
